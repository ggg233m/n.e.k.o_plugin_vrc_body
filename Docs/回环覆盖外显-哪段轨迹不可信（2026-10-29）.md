## 〇、一句话结论

2. 自动出现在 `status()["loop_closure"]` 与 `meta.final.loop_coverage`，

3. 实测口径正确：在线录制里 `060258` = **423 m（48%）**、`024332` = **1 m**，

## 一、为什么是「末段未锚定路程」而不是「覆盖率」

第一版我写了个 `anchored_frac`（被锚定关键帧占比），实测只有 **4–5%**：

| 录制 | 在线回环 | 锚定帧 / 总帧 | anchored_frac |
|---|---|---|---|
| `20261029_060258` | 47 条 | 60 / 1496 | **4.0%** |
| `20261029_024332` | 25 条 | 39 / 772 | **5.1%** |

⚠️ **这个数字低是正常的，不是缺陷**：一条回环只约束 **两个端点**，
不可能覆盖全片（25 条回环最多只碰到 ~50 帧）。拿它当「覆盖率」会误导。

⇒ **主指标改为 `uncovered_m`：从最后一个被锚定的关键帧到末尾的路程。**
这才是「哪段是纯航位推算」的直接回答：

| 录制 | 最后锚定帧 | 末段未锚定 |
|---|---|---|
| `20261029_024332` | kf=770（405 m） | **1 m** |
| `20261029_060258` | kf=801（467 m） | **423 m（48%）** |

`anchored_frac` 保留作「到底有没有回环」的粗参考，docstring 里已写明它不是覆盖率。

## 二、实现

`backend/nav_loop.py`：

```python
self._loop_anchored: set[int] = set()      # __init__

# add_keyframe 里，接受回环时：
self.loops.append(loop)
self._loop_anchored.add(int(a))     # a、b 两端都算锚定
self._loop_anchored.add(int(k))

def coverage(self) -> dict[str, Any]:
    # 末段：从**最后出现**的锚定帧量到末尾
    ...
    return {
        "anchored_kf": int,
        "anchored_frac": float | None,
        "uncovered_m": float | None,        # ← 主指标
        "uncovered_frac": float | None,
        "uncovered_since_kf": int | None,
    }
```

`status()` 用 `**self.coverage()` 合并进去（因此 `status()["loop_closure"]` 自动带上）；
`backend/nav_online.py` 的 `meta.final` 里显式挑四项写出。

## 三、怎么读

```json
"loop_coverage": {"anchored_kf": 60, "uncovered_m": 423.0,
                  "uncovered_frac": 0.475, "uncovered_since_kf": 801}
```

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `uncovered_m` | 末段未锚定路程（世界米） | **> 50 m 就该警惕**；`060258` 是 423 m |
| `uncovered_frac` | 同上，占全程比例 | `> 0.2` 说明两成以上轨迹只有纯航位推算 |
| `uncovered_since_kf` | 从哪个关键帧开始失锚 | 对着点云定位那段区域 |
| `anchored_kf` | 被回环约束过的帧数 | 只作「有没有回环」粗判，**不是覆盖率** |

⚠️ **局限（必须说清）**：

1. **只量尾部**。中段若有一段空洞（之后又出现回环），这个指标看不见 ——
   要看中段得逐帧扫 `_loop_anchored`，本版没做。
2. `uncovered_m = 0` **不等于**轨迹准。它只说「末尾附近有回环约束」，
   不保证漂移被完全修正（`024332` 的末段 1 m，但它的真值对错位仍有 18.8 m）。
3. 小会话（无回环）会报 `uncovered_m: null` —— `null` 是「还没走到能判断」，
   不是「零误差」。别把 `null` 读成好。
