# 长会话漂移-四条路线全否与判据修正（2026-10-30）

> 890 m / 1338 帧这场录制，唯一有效的漂移改善是 `search_max_m` 6→20（真值对 10.42 → 1.14 m）。
> 之后又试了四条路线（回环门槛下调、稠密 ICP 里程、滑窗 BA、ORB-SLAM3 双目），全部否证。
> 过程中发现此前用过的三个指标都不成立，其中一条让三轮 A/B 结论作废。

## 一、可信的起点

先用 3D 重合率钉死「同址」定义（见 `真值对判据-3D重合率把同址钉死（2026-10-30）.md`）：

| 位姿表 | 真值对中位 |
|---|---|
| `poses_full`（在线 47 回环）| **10.42 m** |
| `poses_replay`（重放 85 回环）| **1.14 m** |

7 个 3D 验证过的同址对（点云重合率 0.576–0.844）。
改善来自 `search_max_m` 6→20，**这是本场唯一确定的改善**。

## 二、四条被否证的路线

### 2.1 回环门槛下调 — 无效

| 配置 | 回环 | 后半段 | 真值对中位 |
|---|---|---|---|
| inl50 cov.12（基线）| 85 | 38 | **1.48** |
| inl30 | 134 | 50 | 1.48 |
| inl20 | 186 | 70 | 1.48 |
| inl20 cov.06 | 241 | 88 | 1.46 |
| inl15 cov.04 | 316 | 109 | 1.46 |
| inl10 cov.03 | 421 | 149 | 1.46 |

**回环从 85 涨到 421（5 倍），真值对只从 1.48 变 1.46。**
因此回环数量不再是瓶颈，`min_inliers=50` / `min_coverage=0.12` 保持不变。

### 2.2 稠密 ICP 里程 — 平面几何退化

动机：稀疏 ORB 只解出 **344/1337（26%）** 相邻对的视觉平移，
因为 `des3d` 每帧只有 351 点（中位，p5 仅 37）。而稠密 `pts` 每帧约 84k。

小规模验证看起来很好：

```
收敛 16/16（100%）  内点 68-99%  RMS 0.010-0.115 m  0.6 s/对
```

全量跑完 **1314/1337 = 98%** 覆盖率（1172 s）。**然后用链路一致性检验，立刻崩**：

```
链式累加 1314 步：sum(ICP) = (1011.2, -6.1)  |.| = 1011.2 m
                  sum(底表) = (8.4, -1.0)    |.| = 8.5 m
cosine(ICP 平移, 底表平移) 中位 = -0.018      <- 方向互相垂直
```

**根因：矩形大厅里地板与墙面主导视野，point-to-plane ICP 沿平面滑移时残差几乎不变。**
这是点云配准的经典退化情形。RMS 小不等于解对。

坐标系约定本身是对的（实测 `rms@t0` 在三种候选中最小）：

| 对 | rms@t0（用底表平移）| rms@0（不平移）|
|---|---|---|
| 200-201 | 0.0293 | **0.0148** |
| 600-601 | 0.0225 | 0.0218 |
| 1000-1001 | 0.0624 | 0.4507 |

**不平移时残差反而更小**，正是退化证据。

### 2.3 滑窗局部 BA — 建在坏里程上，结果更差

动机：业界标准（Stereo DSO / BALM / GO-SLAM）都是滑窗局部 BA，
而仓库试过的两个极端是全局最小二乘（`vo_g6` 10.2 cm、`joint_poses` 10.1 cm，
好约束被 80% 无约束帧稀释）和逐对直改（`local_vo_fix` 5.7 cm 但轨迹不连续）。

用稠密 ICP 边跑滑窗（W=60, 重叠 20）：

```
真值对  before 1.14  ->  after 11.65 m
相邻步长 max  1.774  ->  21.687 m   <- 轨迹断裂
```

**输入里程方向余弦 -0.018，输出必然发散。** 这一条不是滑窗的错，是 2.2 的必然结果。

### 2.4 ORB-SLAM3 — 先因配置错，后因场景难

仓库里已装 `ORB-SLAM3`（`.slam_probe/ORB_SLAM3`）与 `RTAB-Map`。

**历史那次（2026-09-19）**，`analysis.json` 显示：

```
Input sensor: Monocular      <- 单目
fx=320, 640x360              <- 数据实际是 fx=303.75, 1080x606 双目
New Map created: 8 次
轨迹 x_range 2.52, z_range 2.49  <- 只有 2.5 m 见方
```

**单目无绝对尺度，这个结果不能判算法。**

**本次改用双目（新写 `make_orbslam3_stereo.py`，正确标定）**：

```
Input sensor was set to: Stereo
First KF:0; Map init KF:0
TRACK_REF_KF: Less than 15 matches!!
Fail to track local map!
mnFirstFrameId = 274   /   mnInitialFrameId = 653
555 Frames set to lost
最终 KeyFrameTrajectory.txt 只有 2 行
```

**场景原因，不是配置**：VRChat 场景大量纯色/低纹理大平面、夜间辉光闪烁、
动态物（玩家/道具）多，1080x606 分辨率偏低，因此 ORB 特征持续不足 15 个匹配。

## 三、三个被推翻的指标（最贵的教训）

| 指标 | 问题 | 代价 |
|---|---|---|
| `own-floor 世界 z` 的 std | **量的不是误差**——它就是「玩家站多高」，世界有平台时本来就该变 | **三轮 A/B 结论作废** |
| 面厚 FWHM | 对米级配准错误不敏感 | 看不出 10 m 错位 |
| ICP 的 RMS | 平面退化时 RMS 仍很小 | 误判 98% 覆盖率为成功 |

跨会话对照证明第一条无判别力：

```
060258（890 m）  floor z std 0.413  range 1.55 m
184318（较短）   floor z std 0.427  range 1.25 m
```

**唯一可靠的判据是「三维几何是否真的重合」**（3D 点云重合率 + 图像证实的同址对）。

## 五、结论：改录制，不改算法

四条算法路线全否之后，剩下的杠杆在**录制侧**：

| 约束 | 本场 | 理由 |
|---|---|---|
| 单次 <= 300 m / <= 240 s | **890 m / 736 s** | 150 帧窗口内部是干净的；整体拼不起来 |
| 每层完整绕圈 | ? | 回环密度 1 条 / 19 m 太稀 |
| 楼梯口停 2 秒 | ? | 关键帧要密，回环才易成 |
| `enable_vertical=True` | False | 多层必需，且需先修 `Grounded→z=0` |

## 七、教训

1. **「收敛 + RMS 小」不等于解对**——平面退化场景里两者都成立且方向全错；
2. **链路一致性是里程的必备检验**：单步看起来再准，累加 1000 步就露馅（1011 m vs 8.5 m）；
3. **判指针错在哪，比指针跑得多快更重要**——三轮 A/B 全废只因用了 `floor std`；
4. **历史否决要先看配置**：单目跑出来的坏结果，不能用来否决双目。
