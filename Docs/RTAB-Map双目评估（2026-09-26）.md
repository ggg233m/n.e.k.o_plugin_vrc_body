# RTAB-Map 双目评估（2026-09-26）

**问题**：ORB-SLAM3 因 GPLv3 和 30 Hz 做不到而不采用（见 `Docs/ORB-SLAM3双目参照评估（2026-09-26）.md`）。
RTAB-Map 能不能同时给出 30 Hz 的位姿（位置自知）和可用的占据栅格（避障）？
**被测**：RTAB-Map 0.23.8 官方 win64 预编译包的 `rtabmap-euroc`（离线回放），输入与 ORB-SLAM3 同一批
SteamVR 合成器镜像双目序列（720×405、fx 202.5、追踪基线 0.063 m、15 Hz）。
**身份**：核心 BSD-3，但**官方预编译包只做研究测试**；vcpkg 端口的 ORB_OCTREE 选项是 GPL，分发前要核对编译选项。

---

## 一、结论（先说）

1. **定位可用，全面优于 ORB-SLAM3。** run4（90 s、真值路程 108.3 m、范围 12.5 m）上，轻量参数的
   建图位姿 ATE（尺度钉 0.755）**0.21 / 0.35 / 0.46 m**，ORB-SLAM3 同一序列是 **0.39 / 1.25 / 1.80 m**。
   RTAB-Map 被测帧 1194–1199、2–4 段；ORB-SLAM3 只有 352–824 帧、4–9 段。
2. **速度达到 30 Hz 的门槛。** 轻量参数里程计单帧中位 **24–25 ms、p90 29–30 ms**（run4），
   ORB-SLAM3 是 44–46 ms。余量只有约 4 ms，而且这是离线回放、不含取帧和后端。
3. **尺度与独立标定一致。** 相似变换尺度 0.757–0.799，标定值 0.755。
4. **回环真的在起作用。** 建图位姿（slam）的 ATE 比纯里程计（odom）低 20–65%。ORB-SLAM3 在这些序列上基本没有回环。
5. **2D 占据栅格不能直接当避障层用。** 720×405 下单像素视差的深度误差约 Z²/12.8（追踪米），
   1.5 m 以外地面噪声就会变成假障碍；只收 1.5 m 以内的观测才干净，但未知区占 80%。见第五节。
6. **优化后的位姿会跳变**（最大一次 0.13 s 里跳 2.13 m），不能直接把位姿连线当"走过的路"。见第六节。

**真值的口径**：OSC 本地速度 + HMD yaw 航位推算（`research/tools/stereo_seq_ground_truth.py`）。它自身也会漂，
run4 OSC 最大空档 9.86 s（零阶保持，按协议语义是正确的）。所以 ATE 是"与航位推算的差"，
**不是绝对精度**，只适合横向比较。

## 二、输入适配（没有改 RTAB-Map 源码）

| 问题 | 处理（`research/tools/prepare_rtabmap_euroc.py`） |
|---|---|
| 官方包缺 `yaml-cpp.dll` | vcpkg 编一个放进 `bin/` |
| 工具按文件名前 10 位解析秒 | 时间戳整体加 1e9 s 偏移（位姿转回时减掉） |
| 工具要求有 IMU 文件 | 写一行放在截止时间之前的占位 `imu0`，**不注入任何假 IMU 数据** |
| 需要每路相机的 `sensor.yaml` | 写 T_BS 与 tx 基线；图像用硬链接，原序列不动 |
| 2D 栅格默认 z 朝上 | T_BS 让 base 系 z 朝上（最初是 y 竖直，障碍被拉成长条） |

位姿用 `research/tools/rtabmap_poses_to_euroc.py` 转回左目光学系：`T_cam = L⁻¹ · T_base · L`，
之后走与 ORB-SLAM3 同一套分析和真值打分。按旧坐标系转换的位姿与改 z-up 之前逐位一致（最大差 0）。

参数组：

| 名称 | 参数 |
|---|---|
| `f2m_default` | 默认 Frame-to-Map |
| `f2m_lite` | `--OdomF2M/BundleAdjustment 0 --Vis/MaxFeatures 600 --OdomF2M/MaxSize 1000` |
| `f2f_flow` | `--Odom/Strategy 1 --Vis/CorType 1 --OdomF2M/BundleAdjustment 0 --Vis/MaxFeatures 600` |

公共参数：`--Rtabmap/CreateIntermediateNodes true`。每组跑 3 次（ORB-SLAM3 已证明单次不能下结论）。

## 三、速度（里程计单帧耗时，每组 3 次）

| 序列 | 参数组 | 中位 ms | p90 ms | 超 33 ms 的帧 | 里程计失败帧 |
|---|---|---|---|---|---|
| run3_640 | f2m_default | 50 / 55 / 68 | 65–109 | 97–100% | 1 / 57 / 183 |
| run3_640 | **f2m_lite** | **24 / 25 / 25** | 31 / 32 / 63 | 6–19% | 0 / 24 / 186 |
| run3_640 | f2f_flow | 30 / 30 / 34 | 44–57 | 32–52% | 30 / 54 / 407 |
| run3_720p | f2m_default | 60 / 60 / 60 | 77–81 | 100% | 4 / 58 / 58 |
| run3_720p | **f2m_lite** | **27 / 28 / 29** | 32 / 33 / 75 | 7–23% | 0 / 1 / 191 |
| run4（z-up） | f2m_default | 54 / 55 / 55 | 66–120 | — | — |
| run4（z-up） | **f2m_lite** | **24 / 24 / 25** | 29 / 29 / 30 | — | — |
| run4 | ORB-SLAM3 双目（对照） | 44 / 45 / 46 | 51–53 | — | — |

- 默认参数的大头是局部 BA（约 22 ms）和配准（约 42 ms）。关掉 F2M 的 BA、特征压到 600 后减半。
- 光流前端（f2f_flow）并没有更快，丢得反而更多；run4 上 3 次都没产出轨迹。**不采用。**
- p90 偶尔跳到 60–75 ms 的那一次，都是有一段丢追、在重新初始化。
- 第一次 run4（y 竖直 base 系）轻量参数测出 35–36 ms，z-up 重跑是 24–25 ms。两次输入图像相同，
  坐标系不影响特征提取和配准，推测是那段时间机器上的其他负载，**但没有查证**。
  run3 上轻量参数也是 24–29 ms，和 z-up 那次一致。30 Hz 余量要在线上复测。

## 四、精度（run4，OSC+HMD 真值，每组 3 次）

odom = 纯视觉里程计，slam = 回环优化后的建图位姿。ATE 单位是世界米。

| 系统 | 位姿 | 被测帧 | 段 | ATE 固定尺度 rmse | p95 | 相似变换尺度 | RPE(2 s) |
|---|---|---|---|---|---|---|---|
| f2m_lite | odom | 1194–1199 | 2–4 | 0.43 / 0.58 / 0.74 | 0.77–1.20 | 0.745–0.761 | 6.2–11.2% |
| f2m_lite | **slam** | 1194–1199 | 2–4 | **0.21 / 0.35 / 0.46** | 0.41–0.76 | 0.757–0.799 | 6.0–8.4% |
| f2m_default | odom | 1086–1197 | 1–2 | 0.23 / 0.33 / 0.43 | 0.44–0.81 | 0.770–0.771 | 5.4–6.6% |
| f2m_default | **slam** | 1086–1197 | 1–2 | **0.19 / 0.21 / 0.23** | 0.38–0.51 | 0.757–0.769 | 5.3–5.7% |
| ORB-SLAM3 双目 | 逐帧轨迹 | 352–824 | 4–9 | 0.39 / 1.25 / 1.80 | 0.59–2.84 | 0.753–0.790 | 9.4–35.1% |

run4 共 1350 帧，真值窗口内约 1200 帧。

- 默认参数比轻量参数准（slam 0.19–0.23 m 对 0.21–0.46 m），但慢一倍，放不进 30 Hz。
  **轻量参数的建图位姿是当前的折中。**
- run3_640 / run3_720p 录于 HMD 采样加入之前，没有位置真值，只能用 `research/tools/analyze_orbslam3_stereo.py`
  验覆盖和尺度（odom 位姿，每组 3 次）：

  | 序列 | 参数组 | 覆盖 | 尺度 s_eff | 尺度 MAD |
  |---|---|---|---|---|
  | run3_640 | f2m_default | 86.4 / 95.8 / 99.9% | 0.765–0.787 | 3.6–6.1% |
  | run3_640 | f2m_lite | 86.2 / 98.2 / 100% | 0.761–0.765 | 5.3–5.5% |
  | run3_640 | f2f_flow | 69.9 / 96.0 / 97.8% | 0.753–0.767 | 5.1–9.8% |
  | run3_720p | f2m_default | 95.7 / 95.7 / 99.7% | 0.758–0.768 | 4.3–4.5% |
  | run3_720p | **f2m_lite** | 85.9 / 99.9 / 100% | 0.762–0.764 | 4.2–4.9% |

  720 + 轻量参数是当前首选：尺度最稳，速度与 640 基本持平。
- 丢追只出现在几处固定的甩头时刻（run3 的 19.5–19.7 s 最常见），换参数也还在；每次丢在哪一处不一样。
  RTAB-Map 丢追后很快重新起一段，被测帧数因此远多于 ORB-SLAM3（后者丢追后常常很久追不回来）。

## 五、占据栅格（避障层）

`rtabmap-reprocess -g2` 从建图库重生成 2D 栅格（`Grid/Sensor 1`、`Grid/3D false`、`Grid/RayTracing true`、
`Grid/CellSize 0.05` 追踪米 = 3.8 cm 世界）。z-up 之后点云的俯视图和侧视图都正常：
轨迹高度只起伏 0.97 追踪米，地面带稳定在相机下约 1.77 追踪米，没有分层。

障碍占比按**已知格**算，未知格从不算进可走区域：

| 设置 | 已知面积 | 障碍占已知格 | 未知占全图 |
|---|---|---|---|
| RangeMax 3.0 m | 93 m² | 22% | 62% |
| RangeMax 2.5 m | 73 m² | 23% | 67% |
| **RangeMax 1.5 m** | 36 m² | **1%** | 80% |
| 3.0 m + SGBM 稠密匹配 | 89 m² | 25% | 66% |
| 3.0 m + 地图系投影 | 83 m² | 41% | 62% |

**原因是深度精度，不是参数。** 地面点的高度中位数在任何距离都稳定，但散布随距离变大：
p95 从近处的 −1.52 漂到 4 m 外的 −0.96（追踪米）。fx 202.5、基线 0.063 时，
1 像素视差的深度误差约 Z²/12.8，1.5 m 以外就会越过地面高度阈值，于是每个观测扇形的外沿都有一圈假障碍。
SGBM 和地图系投影都没有改善。1.5 m 时剩下的障碍落在墙和物体的位置上，看着可信。

### 类 navmesh 原型（`.tmp/navmesh_proto.py`）

链路：RangeMax 1.5 的栅格 → 可走区 → 连通区与多边形 → A* + 路径拉直 → 路径合约，离线约 2 s。

| 项 | 数值 |
|---|---|
| 看到过的地面 | 35.5 m² |
| 只靠"走过"证明能走 | 18.0 m² |
| 障碍 | 0.7 m² |
| 未知 | 144.4 m² |
| avatar 能站的中心区（半径 0.25 m） | 15.9 m²，**10 个孤岛**，最大的占 55% |

三条规划请求：同连通区最远点 → 接受（4.04 m，最窄半宽 0.29 m）；目标在未知区 → 拒绝 `goal_unknown`；
目标在另一孤岛 → 拒绝 `goal_disconnected`。路径合约里有世界米路径点、走廊半宽、限速和停止条件，执行器只读合约。

**孤岛的根源仍是 1.5 m 的观测距离**：两次经过之间的空地没被看到，只能靠走过的那条窄走廊连起来。
所以这套设计要成立，前提是把干净观测距离拉远（第八节）。

## 六、位姿跳变：走廊证据必须 OSC 门控

优化后的位姿会突然跳：最大的一次 0.13 s 里跳 2.13 m，同一步里程计只走了 0.04 m。
第一版直接用位姿连线当"走过的走廊"，凭空画出一条 12 m 的对角通道，规划器也真的从那里走了。

现在的做法：某一步的位姿步长超过 OSC 路程 + 0.15 m，这一步就不算走过。run4 有 49 步被排除。
跳变的具体成因**还没查清**，推测是回环修正在图上分摊不均。

PGM 不带地图原点，栅格和轨迹是搜平移与翻转对齐的：轨迹 84.6% 落在看到过的地面上，第二好的对齐只有 63%。

## 七、没测过的

- **定位模式 / 地图复用**（"位置自知"的另一半）：加载已有地图，只定位不建图。还没跑过。
- **在线运行**：以上全是离线回放（`rtabmap-euroc` 按时间戳回放）。取帧 2.3 ms + 里程计 24–29 ms 在 33 ms 以内，
  但在线的线程调度、后端负载、30 Hz 采集都没测。
- **30 Hz 输入**：序列都是 15 Hz 录的。帧率翻倍时帧间位移减半，理论上追得更稳，没验证。
- **`rtabmap-reprocess -odom`** 重新算里程计会崩（0xC0000409），原因没查。
- **许可**：插件要分发时，得用自己编的 RTAB-Map，关掉 GPL 的可选依赖。官方预编译包只做研究测试。

## 八、下一步

1. **把干净观测距离拉远。** 方向是加大渲染眼距：AnyaDance 驱动的 `Prop_UserIpdMeters_Float` 已改成读
   `headset_ipd_m`，SteamVR 接受 0.126 m（`getEyeToHeadTransform` 实测基线 0.1260，没有被截断）。
   视差翻倍，同样误差下距离约 ×1.4，有望从 1.5 m 推到 2 m 左右。
   **还没验证**：VRChat 是否按新眼距渲染、世界尺度 s 是否仍约 0.755、近处盲区与匹配率。要重录 run5 对比。
2. 全局栅格只收干净距离内的观测，未知保持未知，全局规划只走已知可走格；
   实时避障交给 `backend/local_perception.py` 的近距离判断。
3. 测定位模式和地图复用。
4. 在线跑一次，测 30 Hz 下的真实余量。余量不够时，Basalt（BSD-3）作为备选里程计前端，喂给 RTAB-Map 做建图。

## 九、复现

```bash
# 转成 RTAB-Map 能读的 EuRoC 目录（硬链接，原序列不动；默认 z-up，--legacy-y-up 是旧行为）
.venv/Scripts/python.exe -W ignore research/tools/prepare_rtabmap_euroc.py \
    .slam_probe/stereo_seq/run4 .slam_probe/stereo_seq/run4zup_rtabmap

# 每组参数跑 3 次：读 .slam_probe/stereo_seq/<name>_rtabmap，输出到 .tmp/rtabmap_<name>/<cfg>_r<n>/
bash .tmp/rtabmap_batch.sh run4zup f2m_default f2m_lite

# 位姿转回左目光学系，再用 OSC+HMD 真值打分
.venv/Scripts/python.exe -W ignore research/tools/rtabmap_poses_to_euroc.py rtabmap_slam.txt f_slam.txt
.venv/Scripts/python.exe -W ignore research/tools/stereo_seq_ground_truth.py .slam_probe/stereo_seq/run4 --traj f_slam.txt

# 从建图库重生成 2D 栅格
.slam_probe/rtabmap/bin/rtabmap-reprocess.exe --uwarn -g2 --RGBD/CreateOccupancyGrid true \
    --Grid/Sensor 1 --Grid/3D false --Grid/RayTracing true --Grid/RangeMax 1.5 \
    --Grid/CellSize 0.05 --Grid/NormalsSegmentation true rtabmap.db grid.db
```

批量、汇总和渲染脚本在 `.tmp/`（`rtabmap_batch.sh`、`rtabmap_summary.py`、`run4_gt_summary.py`、
`render_rtabmap_cloud.py`、`navmesh_proto.py`），不进仓库。结果目录：`.tmp/rtabmap_run3_640`、
`.tmp/rtabmap_run3_720p`、`.tmp/rtabmap_run4zup`、`.tmp/rtabmap_run4zup_map`。
