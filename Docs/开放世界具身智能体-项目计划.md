## 0. 执行摘要

这个项目的重心**不在模型，在接口、记忆和运行时**。

四条最重要的判断，后面所有设计都由它们推出：

1. **没有打分点 = 不能训练策略。** 所以必须把"成功/失败"的定义下沉到技能层，让每个技能自带成败判定。这是整个系统唯一的学习信号来源。
2. **几何不是终点，是骨架。** SLAM 只占四层世界表示的最底一层，价值在它上面的语义层和记忆层。世界的消费者是 LLM，不是人。
3. **LLM 绝不能进控制回路。** 各层各跑各的频率，靠状态机异步耦合。把 LLM 写成同步调用，系统会变成一个 PPT。
4. **主干不做端到端学习（不上 VLA）。** 动作低维且被引擎语义化，交给控制器；决策交给 LLM。VLA 解决的是"感知 → 动作"的瓶颈，不是本项目的瓶颈（见 §2.1）。

**最先要做的五件事**（按依赖顺序）：

1. 定义四份 schema，并完成标定（观测 / 动作 / 技能 / 记忆 + 摇杆·双目·头部·**手-相机**）
2. 打通控制通道与感知采集（能驱动 avatar、能同步录帧与音频），确认环境可控
3. 搭运行时骨架：状态机 + 看门狗 + 轨迹回放
4. 做几何与状态估计，用真值对比拿到误差基线
5. 再做**语义层 + 闭环伺服**——这是让系统从"能走"变成"能做事"的第一步（主干不需要训练，见 §11.1）

## 1. 问题定义与约束

### 1.1 观测空间

```
o_t = ( rgb_left, rgb_right, head_orientation, velocity )
```

| 字段 | 性质 | 作用 |
|---|---|---|
| 双目 RGB | 唯一的高维信号 | 公制尺度深度（基线已知，不用学尺度） |
| 头部绝对朝向 | 无漂移姿态参考 | 相当于白送的理想 IMU，消掉姿态漂移 |
| 速度分量 | 直接量测的自运动 | ×Δt 积分即得位移 |

**缺失的东西（必须用其他手段补）**：

- 本体状态：关节构型、末端位姿 → 用**循环隐状态**补（见 §6）
- 力 / 触觉 → **无法补**，直接决定能力边界（见 §17）
- 真值位姿 → 用**回环重定位**补

### 1.2 动作空间

```
a_t = ( joystick_forward, joystick_lateral, head_yaw_delta )
```

- 低维连续，机体坐标系下的**相对量**
- 摇杆语义 = 速度指令；观测里有速度 → 系统近似**一阶运动学**，不需要学动力学
- 头部输出**增量 + 限幅**（不要输出绝对角，否则隐含"瞬移"能力）

**为什么这套动作空间不需要学策略**（这是主干不含 VLA 的直接依据，见 §2.1）：

- **维度低**：摇杆 2 + 头部 2 + 扳机 1 ≈ 5 维；含手部指向也 ≤ 8 维。对比：单臂 7 维、灵巧手 22 维、物理仿真人形全身 30–50 维。
- **语义层级高**：输出是"前进 / 转向"这类**被引擎抽象过的语义指令**，不是关节角或力矩。动作 → 效果的映射由引擎保证，确定且光滑，**没有接触、摩擦、不连续性**——那才是灵巧操作真正难的地方。
- **结论**：动作交给**控制器**，决策（难的那一半）交给 LLM。这正是主干不含 VLA 的原因。
- **精确性靠闭环，不靠维度**：需要"对准"时（如指向开关）由闭环视觉伺服给精度，不是靠更大的模型。
- **何时才需重新考虑学习策略**：只有当必须**逐关节控制一个物理仿真本体、且没有动画系统兜底**（30+ 维连续、接触丰富）时。

**若将来确实要学控制层**（仅在满足 §11.1 前置条件时）：先确认摇杆是模拟量（连续）还是四向二值——前者用高斯策略（PPO / SAC），后者用离散动作头。**当前阶段不做这件事。**

### 1.3 任务性质

| 属性 | 含义 | 设计后果 |
|---|---|---|
| 开放世界 | 场景大、内容多样、非预设 | 世界表示必须可扩展、可遗忘 |
| 无外部目标 | 目标需自生成 | 需要内在动机机制 + 人设锚点（见 §8） |
| 无打分点 | 没有外部 reward | 打分点必须下沉到技能层 |

### 1.4 由约束推出的三条设计原则

- **原则一：打分点下沉。** 技能层承担成败判定，低层才有学习信号，上层才有规划依据。
- **原则二：几何 + 语义叠加。** 不接受"点云本身就是世界理解"这种说法。
- **原则三：异步分层。** 频率差两到三个数量级，必须异步。

## 2. 系统架构

### 2.1 智能分布：主干不含端到端学习的策略

本项目**没有**用神经网络端到端地做"视觉 → 动作"。智能分布在三处，没有一处需要训练：

| 来源 | 负责什么 | 是否训练 |
|---|---|---|
| 经典几何 | 我在哪、怎么走（SLAM / navmesh / 控制器） | 否 |
| VLM | 看懂画面、说清场景（检测 / 深度 / 开放词汇） | 否（用现成预训练） |
| LLM | 决定做什么、怎么说（目标 / 技能选择 / 人设 / 社交） | 否 |

**VLA 不在主干内**（依据见 §1.2 / §10.2）：它的价值在"像素 → 高维连续动作"难以手工建模时；本项目动作低维且被引擎语义化，控制器即可。本项目的瓶颈是**语义**与**社交**，而 VLA 两者都不解决。

### 2.2 主流水线

以"把灯关了"为例，一次交互任务的完整链路：

| # | 环节 | 做什么 | 谁负责 | 时机 |
|---|---|---|---|---|
| 01 | 感知 | SLAM 定位 + 语义标注（增量，每项带 `confidence` / `last_seen`） | 经典 + VLM | 持续 |
| 02 | 记忆 | 检索附近实体 + 情节记忆（来过吗、上次成功吗） | 自研 | 持续 |
| 03 | **决策** | 读世界 + 指令 → 选定目标与技能 | LLM | **出发前** |
| 04 | 预检 | affordance：能交互吗？够得着吗？ | 查表 + 几何 | 出发前 |
| 05 | 导航 | 走到**交互位姿**（位置 + 朝向，不只是距离） | navmesh 寻路 + 控制器 | 1–10 Hz |
| 06 | **对准** | 闭环伺服：观测偏差 → 调整 → 再观测 | 视觉伺服 | 10–30 Hz |
| 07 | 执行 | 触发 + 判定成败 → 回写记忆 | 技能 | 事件驱动 |

两条必须写进代码的纪律：

- **决策在出发前，校验在到达后。** 03 决定"该不该做"；到达后（06）只做"目标还在吗、对准了吗"的校验，不重新决策。顺序反了会白走，而且把"该不该做"拖到行动前一刻是危险的。
- **检测 ≠ 对准。** 手部位置通常**无需检测**（自己控制的，从输入 / 骨骼已知）；需要的是手与目标的相对关系（**手-相机标定 + 深度**）。检测是**一次观测**，对准是**收敛过程**，二者不可合并。

### 2.3 分层结构（自上而下）

```
        ┌──────────────────────────────────────────┐
        │  决策层 · LLM                             │  0.1–1 Hz  不训练
        │  读世界 + 指令 → 目标 + 技能选择             │
        └───────────────────┬──────────────────────┘
                            │ 技能调用（含参数）
        ┌───────────────────▼──────────────────────┐
        │  技能层 · 技能库 + affordance 表            │  1–10 Hz   查表/程序
        │  前置条件 · 参数 · 后效 · 超时               │
        └───────────────────┬──────────────────────┘
                            │ 子目标 / 运动意图
        ┌───────────────────▼──────────────────────┐
        │  运动层 · 生成式动作模型（可选）             │  10–30 Hz  预训练
        │  先动画库 + motion matching，不够再上生成式   │
        └───────────────────┬──────────────────────┘
                            │ 运动 / 目标位姿
        ┌───────────────────▼──────────────────────┐
        │  控制层 · 闭环伺服 + 控制器                  │  30–100 Hz 不训练
        │  视觉伺服对准 · 位姿控制 · 导航跟随           │
        └───────────────────┬──────────────────────┘
                            │ 控制指令
                            ▼  摇杆 + 头部朝向 + 扳机
```

频率差 2–3 个数量级 → 必须异步耦合，**LLM 绝不进控制回路**（见 §5）。

### 2.4 组件职责表

| 组件 | 频率 | 输入 | 输出 | 是否训练 |
|---|---|---|---|---|
| 决策层 | 0.1–1 Hz | 记忆文本视图、指令、人设 | 目标 + 技能调用 | 否 |
| 技能层 | 1–10 Hz | 技能定义 + 世界 / 自身状态查询 | 子目标 / 控制程序 | 否（查表 + 程序） |
| 运动层 | 10–30 Hz | 技能意图、目标位姿 | 运动序列 / 播放指令 | 否（现成模型 / 动画库） |
| 控制层 | 30–100 Hz | 观测 + 目标位姿 | 摇杆 / 头部增量 / 扳机 | 否（控制器 + 伺服） |
| 记忆 | 持续 | 观测 + 执行结果 | 子图图 / 情节流 / 检索结果 | 部分（感知模型） |
| 自我模型 | 持续 | 动作指令 + 观测速度 | 本体状态 / `self_pose`（见 §6） | 否（状态估计） |
| 失效检测 | 持续 | 位姿 / 速度 / 内部标志 | `LOST` / `RECOVERING`（见 §18） | 否（阈值 + 规则） |
| 运行时 | 持续 | 全局 | 调度、看门狗、回放 | 否 |

### 2.5 世界表示：SLAM 只占最底一层

四层栈（自下而上构建）：

| 层 | 内容 | 谁来提供 |
|---|---|---|
| 1. 几何骨架 | 点云 · 栅格 · TSDF | **SLAM / VO** |
| 2. 开放词汇语义 | 每个体素挂 CLIP / SigLIP 特征 | 检测/分割 + VLM |
| 3. 分层语义地图 | 几何 / 语义 / 决策三层，VLM 可读 | 自研 |
| 4. 情节与图记忆 | 时间线 + 实体关系 + 检索 | 自研 |

**对本项目的具体取舍**（因为已有头部绝对朝向 + 速度）：

| SLAM 模块 | 是否需要 | 原因 |
|---|---|---|
| 姿态估计 | 不需要 | 头部绝对朝向已提供 |
| 视觉里程计（平移） | 需要，但轻量 | 速度积分足够，只是会漂 |
| 回环检测 / 重定位 | **需要** | 唯一缺的东西：消除平移长期漂移 |
| 建图（多帧融合） | 需要 | SLAM 不可替代的部分 |
| 语义 | 范畴外 | 完全不在 SLAM 里 |
| 语言查询接口 | 范畴外 | 完全不在 SLAM 里 |

**传统 SLAM 不能直接拿来当世界理解的三个原因**：

- 表示形式不对：点云/栅格无语义，LLM 无法查询
- 没有时间维度：地图是"当前状态"，不是"我 5 分钟前见过它"
- 没有实体概念：地图里没有"那个箱子"这个可被引用的对象

**动态物体**：传统 SLAM 假设静态刚性环境，开放世界会被打破。必须加置信度衰减 + 观测计数剔除，不能直接搬。

**地图是子图图结构，不是单一全局地图**：位姿失效（掉坑、大跨度传送等）后全局坐标会直接失效，必须

- 开**新子图**（新局部坐标系）继续运行，不再依赖旧全局坐标；
- 靠**视觉地点识别**（place recognition）重连子图，且**不保证一定能接上**——接不上就当新地图继续探索；
- 因此**技能不得绑死全局坐标**，必须能在局部坐标系里工作。

### 2.6 架构原则

1. **能查表 / 几何解决的，不交给 LLM。** LLM 只用于需要理解语义和做取舍之处；确定性的事（按钮类型判定、对齐确认）由 affordance 表与伺服环承担。交给 LLM 既慢、又贵，还会幻觉。
2. **闭环优先于开环。** 精度来自反馈（视觉伺服），不来自模型容量；闭环还能自愈标定误差。
3. **标定是关键路径。** 手-相机外参是交互类任务的硬前提（见 §4）。
4. **决策在出发前，校验在到达后**（见 §2.2）。
5. **地图是子图图结构**，技能不绑全局坐标（见 §2.5）。
6. **LLM 绝不进控制回路**，各层异步耦合（见 §5）。

## 3. 接口契约

> 并行开发时，这里最先出问题。四份 schema 必须版本化，且跨模块只通过 schema 通信，禁止直接读对方内部状态。

### 3.1 观测 schema

```yaml
Observation:
  t: float                    # 单调时钟，秒
  rgb_left: uint8[H,W,3]
  rgb_right: uint8[H,W,3]
  head_orientation: float[4]  # 四元数，世界系，绝对
  velocity: float[3]          # 机体坐标系，m/s
  valid: bool                 # 缺帧必须显式标记
```

约束：
- 所有字段携带**同一个**时间戳，由采集层统一打戳
- 图像与速度/朝向频率不同，**消费方负责插值**，生产方不负责对齐
- 缺帧可容忍，静默丢帧不可容忍

### 3.2 动作 schema

```yaml
Action:
  t: float
  joystick: float[2]              # [-1, 1]²，机体坐标系
  head_yaw_delta: float           # 弧度，已限幅
```

### 3.3 技能 schema

```yaml
Skill:
  name: str
  description: str         # 给 LLM 看的自然语言描述
  params_schema: JSONSchema
  preconditions: [str]     # 执行前校验
  timeout: float           # 秒
  postcondition: str       # 成败判定的定义
  interruptible: bool      # 能否被抢占

SkillCall:
  skill: str
  params: dict
  issued_at: float

SkillResult:
  status: "success" | "failed" | "timeout" | "preempted"
  detail: str
  evidence: dict           # 用于反思的观测摘要
  finished_at: float
```

**硬性约束**：

- 每个技能**必须**有 `postcondition`。没有成败判定的技能不允许注册——它是整个系统唯一的打分点来源。
- LLM 只能输出 `SkillCall`，参数必须过 JSONSchema + 值域校验，不合法直接拒绝并把错误回传给 LLM 重试
- 粒度经验值：**每个技能 1–10 秒可完成**。太细 → 上下文爆炸 + 组合爆炸；太粗 → 遇意外无法应对

### 3.4 记忆 schema

```yaml
Entity:
  id: str
  type: str                 # 开放词汇
  embedding: float[D]
  position: float[3]
  extent: float[3]
  last_seen: float
  observation_count: int
  confidence: float
  provenance: [frame_id]    # 必填

Episode:
  id: str
  t_start: float
  t_end: float
  summary: str              # LLM 生成的自然语言摘要
  importance: int           # 1–10，写入时打分
  embedding: float[D]
  entities: [Entity.id]
  outcome: "success" | "failed" | "aborted"
```

**硬性约束**：

- 所有记忆写入**必须带 provenance**。LLM 没有写权限。
- 冲突用 `confidence` + `last_seen` 裁决

### 3.5 契约版本管理

- 四份 schema 各自带版本号（语义化版本）
- 契约变更必须同步更新：校验器 + 单元测试 + 跨模块回归测试
- 破坏性变更需并行支持两个版本至少一个迭代周期

## 4. 标定与时间同步

> 这一节原计划缺失，但它是所有状态估计与训练的前置条件。**标定不准，后面全部白做。**

### 4.1 标定清单

| 标定项 | 方法 | 频率 | 影响 |
|---|---|---|---|
| 双目内参 + 畸变 | 棋盘格 / AprilTag + `calibrateCamera` | 一次（变焦/碰撞后重做） | 深度精度 |
| 双目外参（基线、R、T） | `stereoCalibrate` | 一次 | 深度尺度 |
| head → camera 外参 | 已知安装位姿 / 手眼标定 | 一次 | 头部朝向与视觉的一致性 |
| **手 / 末端 → camera 外参** | 手眼标定 | 一次 + 定期复检 | **交互类任务（指向、够取）的硬前提**，见 §4.4 |
| **摇杆指令 → 实际速度** | 逐轴扫掠，拟合增益 + 死区 + 饱和 | 一次，且随负载漂移要复检 | **最关键**，见 4.2 |
| 时间偏移（相机 vs 速度/朝向） | 阶跃响应 / 互相关 | 一次 + 定期校验 | 位姿积分漂移 |

**深度尺度问题**：内参外参固定 → 视差直接转公制深度，**不要让网络去学尺度**。若标定有误，网络会学一个"补偿标定误差"的映射，换场景即崩。

### 4.2 摇杆标定（重点，最容易漏）

这是本项目特有的坑：观测里有速度，动作里有摇杆，两者的关系决定了系统的"运动学先验"。

- 必须逐轴标：`v_forward = f(joy_forward)`、`v_lateral = g(joy_lateral)`，各自含死区、增益、饱和
- 头部：`Δyaw/s = h(head_cmd)`，测最大角速度用于限幅
- 标完后写成**可查询的配置文件**，控制层、技能层、affordance 都读它
- 若不标死 → 下游会隐式补偿这个错误：在标定环境里能跑，一换参数就废

### 4.3 时钟与时间同步

- **单一时间源**：仿真/运行时提供单调时钟，所有模块统一用它打戳
- **禁用**各模块自行调 `time.time()`——多来源时钟必然错位
- 仿真时间 ≠ 墙钟：训练用仿真步，评估与日志用仿真时间；两者都记录，用于计算实时率（RTF）
- 图像与低频信号频率不同：生产方不补齐，**消费方按时间戳插值**（与 §3.1 一致）
- 回放依赖时钟：回放器必须能按记录的时间戳**原速或加速**重演（见 §16.4 回放测试）

### 4.4 手-相机标定与闭环伺服（交互任务的硬前提）

要做"准确指到开关并按下去"这类任务，标定**从工程细节升级为关键路径**：

- **手 / 末端 → 相机外参**：不知道手在相机坐标系里的位姿，就无法用相机观测算出手该指向哪——"准确"二字无从谈起。
- **闭环伺服，不是开环动画**：执行分两步——① 感知目标的精确 3D 位置（检测 + 深度）；② 迭代对准：观测手与目标的偏差 → 调整手部朝向 → 再观测 → 收敛 → **对准验证通过后才触发**。
- **闭环的好处**：**自愈标定误差**。开环播动画则误差会直接暴露成"空按"。
- **多类型开关**：用**技能分派表**（类型 → 瞄准点 / 触发方式 / 期望后效）；类型判断**不要交给 LLM**（见 §2.6）。

## 5. 运行时与调度

> 这一节决定系统能不能连续跑 8 小时，比模型选型重要得多。

### 5.1 多时间尺度

| 层 | 频率 | 调度方式 |
|---|---|---|
| 控制层 | 30–100 Hz | 常驻循环，**不等待任何人** |
| 技能层 | 1–10 Hz | 按需触发 |
| 决策层 | 0.1–1 Hz | **完全异步**：请求发出后立即返回，回调进待处理队列 |

LLM 单次调用延迟 1–10 秒，绝不能阻塞控制层。控制层用**当前最优的子目标**持续跑，新意图到达时按抢占规则处理。

### 5.2 状态机

```
IDLE ──► EXECUTING ──► IDLE
  │          │
  │          ├──► WAITING_LLM   （执行完/失败，等新意图）
  │          │
  └──────────┴──► RECOVERING   （检测到故障，执行恢复策略）
                    │
                    └──► HALTED  （不可恢复，需人工介入）
```

### 5.3 技能抢占规则

| 情况 | 处理 |
|---|---|
| 新意图到达，当前技能 `interruptible=true` | 立即抢占 |
| 新意图到达，当前技能不可中断 | 进队列，等当前技能自然结束 |
| 抢占发生 | **必须**写 `SkillResult(status="preempted")` |
| 同一技能在短窗口内重复下发 | 去重，只执行一次 |

**抢占必须留痕**，否则记忆里会出现"断头轨迹"，反思阶段会得出错误结论。

### 5.4 看门狗与崩溃恢复

| 机制 | 触发条件 | 动作 |
|---|---|---|
| 心跳看门狗 | 控制层超时 N ms 无心跳 | 摇杆归零 → `HALTED` |
| 技能超时 | 超过 `timeout` | 强制结束，写 `timeout`，交回决策层 |
| 记忆事务 | 写入过程 | 要么 Episode 完整落库，要么不落 |
| 进程重启 | 启动时 | 从最后一个**完整** Episode 恢复，丢弃未完成的 |

### 5.5 可观测性（不是 nice-to-have）

必须能**完整回放**。每步记录：

- 观测摘要 + 动作 + 技能调用
- LLM 输入输出摘要 + token 数 + 延迟
- 记忆变更日志（谁写的、写了什么、依据哪一帧）

需要的工具：
- 轨迹回放器（可视化 + 时间轴，可逐帧定位）
- LLM 调用账本（成本与延迟监控）
- 记忆变更浏览器

> 无目标系统的故障几乎都是"看了日志才发现它在三小时前就漂了"。没有回放能力，排障只能靠猜。

## 6. 自我模型与本体感知

> 原计划完全缺失这一块。但"没有外部目标"的系统，第一步是知道自己是谁、能做什么。

### 6.1 要建模的三件事

| 内容 | 为什么需要 | 怎么得到 |
|---|---|---|
| 本体状态（云台/关节构型） | 观测里没有，必须内部维护 | 指令积分 + 循环隐状态 |
| 自身几何边界（碰撞体积） | 判断能否穿过缝隙、能否贴近 | 离线标定 + 保守包络 |
| 运动学限制 | 规划时不能假设瞬时转向 | 标定：最大线速度 / 角速度 / 加速度（见 §4.2） |

### 6.2 放在哪一层

| 层 | 自我模型的形态 |
|---|---|
| 控制层 | 显式 `self_pose`（状态估计产生）作为伺服与位姿控制的输入 |
| 技能层 | **显式**保留 `self_pose`（位置 + 朝向 + 速度 + 边界），由状态估计产生，不是学出来的 |
| 决策层 | 只读，用于回答"我现在在哪、朝哪、能不能挤过去" |

`self_pose` 必须写进记忆的即时层，并作为技能层在线的可查询状态。

### 6.3 与 affordance 的关系

`p_affordance` 必须包含一项"**以我的体积/运动学能否做到**"，否则会规划出物理上挤不过去、或过不去的路径。

> 判断"能不能"的前提是先有"我是什么"。自我模型是 affordance 的输入之一，不是可选项。

## 7. 世界表示与记忆

### 7.1 几何骨架

- 双目 → 视差 → 深度。SGBM 起步，追求质量换 RAFT-Stereo / FoundationStereo
- **必须同时计算视差置信度掩码**。无纹理、反光、透明区域的视差是垃圾数据，直接喂给后面会污染训练
- 表示：滚动窗口 TSDF / 体素占据栅格
- 位姿：`速度 × Δt` 前向积分 + 头部绝对朝向校正姿态 + 回环重定位消除平移漂移
- 动态物体：置信度衰减 + 观测计数剔除
- 内外参固定 → 标定一次，深度天然是公制，**不要让网络去学尺度**

### 7.2 开放词汇语义

每个非空体素存储：

| 字段 | 说明 |
|---|---|
| position | 3D 坐标 |
| embedding | CLIP / SigLIP 特征向量 |
| observation_count | 观测计数（用于置信度） |
| source_frame_id | 来源帧（provenance） |
| last_seen | 最近观测时间 |

实例化由检测 / 分割模型驱动。

### 7.3 分层语义地图

| 层 | 内容 |
|---|---|
| 几何层 | 可通行区域 + 障碍物 |
| 语义层 | 物体 + 物体间关系 |
| 决策层 | 供上层任务使用的高层结构 |

对外表现：**多通道俯视图 + 结构化查询接口**。这一层是"让 LLM 了解整个世界"的落地点——把 3D 信息转换成 VLM 能读的表示。

### 7.4 情节与图记忆

| 层级 | 内容 | 技术 |
|---|---|---|
| 即时 | 近期感知 | 滑动窗口，进程内 |
| 长期 | 语义召回 + 关联扩散 | 向量库 + 图数据库（Neo4j） |
| 不可变 | 安全规则、身份锚点 | 只读，每次决策强制生效 |

- 实体图：物体、地点、关系
- 情节流：时间线事件，自然语言描述

### 7.5 检索

```
score = w1 · 归一化(recency) + w2 · 归一化(importance) + w3 · 归一化(relevance)
```

- `recency`：指数衰减
- `importance`：写入时由 LLM 打 1–10 分，只打一次
- `relevance`：embedding 余弦相似度
- 权重建议先取 1 : 1 : 1，再按实际表现调

### 7.6 反思与遗忘

**反思**：
- 触发条件：近 N 条记忆的累计 `importance` 超过阈值（不是定时触发）
- 产出：高层结论（例："我不擅长开这种柜门"）
- 产出写回记忆流，成为可检索节点

**遗忘**：
- 按重要性 + 时间双重衰减
- 低分旧记忆降采样为统计摘要
- **硬性上限**：记忆条目数有硬上限，超出必须压缩。没有这条，系统会越跑越慢越蠢。

### 7.7 写入权限与冲突裁决

| 数据 | 谁能写 |
|---|---|
| 实体 / 几何 | 只有感知系统 |
| Episode outcome | 只有控制层的结果 |
| 摘要 / 反思 | 反思模块 |
| 安全规则 / 身份 | 人工（一次写入，不可变） |
| **LLM** | **只有读权限** |

这是防记忆幻觉的**预防性**设计，不是事后补救。

冲突裁决：`confidence` 高的赢；两者都低则标记为冲突并触发**主动重新观测**（见 §9）。

## 8. 目标生成与内在动机

> "无外部目标"不等于"无目标"。目标必须由系统自己生成，且必须能被机器判定。这一节原计划只点名了"自提目标/自动课程"，这里补上机制。

### 8.1 目标的三种来源

| 来源 | 机制 | 触发时机 |
|---|---|---|
| 持续需求（drives） | 人设锚点定义的驱动力（见 8.5） | 常驻 |
| 认知缺口 | novelty / 信息增益：去哪能最大化对世界的知识增量 | 当前目标完成或失败后 |
| 技能缺口 | 学习进度：哪个技能的 affordance 长期偏低 → 针对性练习 | 定期扫描技能库 |

### 8.2 三类内在奖励

注意：这些**不是外部 reward**，只在目标层与技能层内部用于排序和课程。

| 类型 | 定义 | 单独使用的反例（会崩） |
|---|---|---|
| 新颖性 novelty | 状态/区域访问频率的倒数 | 只追 novelty → 永远冲向最陌生的噪声，退化成乱逛 |
| 信息增益 | 预期能降低地图/记忆熵的程度 | 只追信息增益 → 反复扫同一面墙的细纹 |
| 学习进度 | 某技能成功率的提升速率 | 只用成功率 → 卡在简单技能上刷分 |

**实践建议**：取三者加权和，权重**不是常数**，按学习进度动态调——哪块在长就压哪块的权重。这是 SOP，不是拍脑袋。

### 8.3 目标语法（必须可判定）

自提目标**禁止**只生成一句自然语言，否则"完成率"这个指标失去意义。必须落成可校验结构：

```yaml
Goal:
  id: str
  source: "drive" | "curiosity" | "skill_gap"
  description: str            # 自然语言，给人看
  target_predicate: str       # 机器可判定，例："entity:箱子_7 的位置已写入记忆"
  deadline: float | None
  priority: float
  status: "active" | "done" | "abandoned"
```

**没有 `target_predicate` 的目标不允许进队列。**

### 8.4 自动课程

课程不是预设的难度阶梯，而是**由 affordance 分布自动排序**：

- 优先练"当前成功率 30–70%"的目标（太难没信号，太易没收益）
- 太难 → 拆解为子目标；太易 → 退役并提高难度

这条规则同时解决了"没有外部目标时练什么"和"课程从哪来"两个问题。

### 8.5 人设与身份锚点

**人设 = 一组常驻驱动力 + 行为约束**，写在不可变记忆里，每次决策层决策强制注入。

| 组成 | 内容 | 作用 |
|---|---|---|
| 驱动力 | 例：维持探索、保持安全、对特定类别好奇 | 提供"无外部目标时的目标来源" |
| 风格 | 例：谨慎/激进、动作快慢偏好 | 让行为有一致性，便于评测自洽性 |
| 能力自述 | 我有什么技能、没有什么 | 抑制 LLM 提出做不到的计划 |
| 硬边界 | 绝对不做的事 | 安全底线 |

**关键**：人设不是 prompt 里一句话，而是**结构化的、每次决策都注入的常量**。它决定系统的下限（不失控）与人格（可复现的行为风格）。

### 8.6 冷启动

系统从零开始时：记忆空、技能库空、affordance 无数据。bootstrap 顺序：

1. **脚本专家先行**：跑一批演示，填第一批技能 + affordance 标签
2. **人在环（可选）**：teleop 采集少量种子技能
3. **记忆预热**：先跑一遍场景，把静态实体写进长期记忆，避免开局"失忆"
4. **技能库种子**：给 LLM 一个最小技能集（移动、转头、看、靠近），让它组合出更多

没有冷启动设计，系统开局会长时间低效乱逛，且把"乱逛"写进记忆，污染后续。

## 9. 主动感知与探索

> 双目 + 头部朝向给了主动视觉的物理自由，但原计划只写了"主动扫视"四个字。

### 9.1 三种主动感知动作

| 机制 | 做法 | 解决什么 |
|---|---|---|
| Next-Best-View | 选一个头部朝向，使关键区域的信息增益最大 | 遮挡、看不清 |
| 探索前沿 frontier | 朝"已知与未知的边界"移动 | 空间覆盖率 |
| 主动扫视 | 走动中周期性转头回扫身后 | 视野外一致性、防盲区 |

### 9.2 信息增益怎么算

用两个可计算量：

- 体素地图的**占据不确定性下降量**
- 记忆里**低 confidence 实体**的期望置信度提升

两者归一化后加权。**不要用"预测下一帧像素误差"当增益**——它会偏爱高纹理噪声区。

### 9.3 探索与利用的平衡

没有外部目标 → 不存在传统 bandit 意义上的"利用"。

- 基调由**驱动力（人设）**定：探索型 vs 稳定型
- 局部调节由**学习进度**做：某技能在长就多利用它，停滞就转探索

**探索终止与重置**见 §13.4。

## 10. 模型选型

### 10.1 选型表

| 层 | 选型 | 说明 |
|---|---|---|
| 决策层 | 前沿 LLM（或本地 Qwen 系） | 选目标、选技能、人设、社交；输出结构化 SkillCall；必须异步 |
| 技能层 | 代码即动作（LLM / 人写控制程序）+ affordance 表 | 可组合、可验证、可累积（沙箱见 §16） |
| 技能层 affordance | 先查表；需要时训小型分类器 | **在规划循环里高频调用，必须快**；标签来自技能成败记录 |
| 语义 / 开放词汇 | 预训练 VLM + 开放词汇检测 + 深度 | Qwen3-VL / Grounding DINO / YOLO-World；双目 SGBM 或 Depth Anything |
| 运动层 | 动画库 + motion matching（首选）→ 生成式动作模型（补长尾） | 补"动得自然"；**它是运动生成器，不是策略**（见附录 B） |
| 控制层 | 闭环视觉伺服 + 位姿 / 导航控制器 | 不训练；精度来自反馈（见 §4.4） |
| 记忆 | 向量库 + 图数据库 + 子图几何地图 | 见 §7 |
| 仿真 | 可选，非必需 | 本项目的分布来源是真实客户端离线实例（见 §11.1） |

### 10.2 为什么主干不用 VLA

**结论先说：主干不用 VLA**（见 §2.1 / §1.2）。下面说明为什么"套不上"，以及万一将来需要（判据见 §1.2）能借什么。

主流 VLA（π0 / GR00T / Helix）的输出都是 **7-DoF 关节角或末端位姿**，本项目的动作空间是 **2 维摇杆 + 1 维头部朝向 + 1 维扳机**——**动作头对不上，预训练权重用不了**。

可以借的：
- 视觉语言骨干
- flow matching 的动作生成配方
- 特权教师 → 学生蒸馏的训练配方

不能借的：动作头权重。

参考对照（判断借哪部分）：

| 模型 | 视觉编码器 | 骨干规模 | 动作头 | 动作空间 |
|---|---|---|---|---|
| π0 | PaLI 系 | ~3B | Flow Matching | 连续（关节 + EEF） |
| GR00T N1 | Eagle | ~2B | 双系统（DiT + MLP） | 连续全身 |
| Helix | — | 80M S1 + 7B S2 | 双系统 200Hz | 连续 |
| Gemini Robotics 1.5 | Gemini | — | 自回归 + 动作模态 | 连续 |
| OpenVLA | SigLIP 400M | LLaMA 2 7B | 离散 tokenization | 256 bins/维 |

### 10.3 模型规模的边界

| 层 | 规模倾向 | 原因 |
|---|---|---|
| 控制层 | 无模型（控制器） | 求延迟，30–100 Hz |
| 语义感知 | 中小（用现成预训练） | 求延迟与显存 |
| 技能层 affordance | 很小 | 在规划循环里高频调用 |
| 决策层 | 大 | 求推理质量，频率低所以延迟不敏感 |

## 11. 训练方案

### 11.1 训练边界：主干不训练

新架构（§2）里主干没有任何需要训练的组件：

| 组件 | 训练方式 |
|---|---|
| 决策层 | **不训练**，靠提示 + 人设 + 自动课程 |
| 技能层内容 | 不训练，靠 LLM / 人编写 + 执行反馈迭代 |
| 运动层 | 不训练（用现成动画库 / 预训练模型） |
| 控制层 | **不训练**（控制器 + 闭环伺服） |
| 语义感知 | 不训练（用现成预训练模型） |
| affordance | 可选训练（有监督，标签来自技能成败记录）；起步可先用查表 |

**唯一值得主动"学"的**是 affordance 校准（"这东西到底能不能动"）——它是本项目唯一能自动获得、且可放心试错的监督信号（地图可重置）。

> 关键：把"没有打分点"限制在最上层。技能层内部必须有明确的成功条件（`postcondition`），否则系统连 affordance 都无法校准。

### 11.2 控制层策略训练（前置条件未满足，暂不做）

> 本节仅在满足以下条件时才启动：① 必须逐关节控制物理仿真本体（无动画系统兜底）；② 已积累 (状态, 动作) 数据；③ 有可用的成功信号。**当前架构用控制器替代策略，不需要它。**

**阶段一：特权教师 RL**

- 仿真里训练能看到真值位姿、真值深度、目标位置的教师策略
- 用 RL（PPO / SAC）或脚本专家
- 这一步决定控制层的性能上限，不能省

**阶段二：DAgger 蒸馏**

- 关键细节：**纯行为克隆会失败**。当学生观测缺少关键特征（遮挡等），BC 损失不足以保证正确行为
- 必须让学生跑自己的 rollout，由教师在这些状态上标注（DAgger）
- 同时配**激进的视觉域随机化**：纹理、光照、曝光、运动模糊、相机基线/焦距/噪声
- 本项目是虚拟世界，随机化重点是**跨场景的光照 / 材质 / 布局多样性**

**阶段三：学生自举 RL**

- 用**二值成功信号**跑 GRPO（只有 actor 的 PPO 变体）继续微调
- 预期效果：自动学出"**主动把关键区域保持在视野内**"——也就是主动扫视
- 这一条对双目方案尤其重要：它是观测受限的补偿手段，而且是自举出来的，不需要手工设计

### 11.3 技能层

三种主流做法，可组合：

| 做法 | 适合 | 要点 |
|---|---|---|
| 代码即动作 | 动作空间可编程 | 技能就是函数，用执行反馈 + 自验证迭代 |
| 技能库维护器 | 想自动演化技能库 | 训一个模型做 add / refine / merge / remove，执行器冻结 |
| 可行性打分 | **必须有** | LLM 提技能（Say）× affordance 判可行性（Can） |

**SayCan 式公式值得直接抄**：

```
p_combined = p_LLM(技能 | 指令) × p_affordance(能成功 | 状态)
```

`affordance` 模型是整个系统里最值钱的组件——它同时是：
- 规划约束（不选做不了的技能）
- 学习信号（把无打分点变成有局部打分点）
- 评测指标（预测成功率与实际成功率的相关性）

### 11.4 辅助自监督任务（稳住表征）

> 无标注视频**只能**提供下面这类信号（表征 / 动力学），**给不了动作**——它喂不了策略，只能喂表征。本项目不自训 VLA，直接用现成预训练模型即可白拿这部分红利（见 §10.1）。

- 深度 / 视差回归
- 未来帧预测（世界模型）——逼表征编码物理规律
- 逆动力学：从 `(o_t, o_t+1)` 预测动作
- 时序对比：用"绝对朝向"构造正样本，同一地点不同视角的表示应当一致

## 12. 数据管线

### 12.1 数据来源与配比（依赖前置条件）

> **本节前提依赖 §11.1 的判定。** 主干不训练时，数据的用途从"训策略"变成"离线标注 / affordance 校准 / 表征"。下表按当前约束（1x、无特权信息、可重置）给出可用来源。

| 来源 | 用途 | 说明 |
|---|---|---|
| 脚本注入 + 录帧 | **配对 (状态, 动作) 的免费生产线**（并行、24/7、确定性） | 覆盖状态空间；但动作不是专家示范，**只能训表征 / 动力学，不能训策略** |
| 无标注视频 | 自监督表征 / 世界模型 | 只给"怎么看世界"，不给"你怎么动"（见 §11.4） |
| 人类示范（主动挑选） | 策略与技能的**专家信号** | 人的时间不可并行，是硬上限 → 用不确定性主动挑状态（Active Learning） |
| 技能成败记录 | **affordance 标签** | 本项目唯一能自动获得、且可放心试错的监督信号（地图可重置） |
| 失败样本 | 反例 | 不能省 |

**本项目没有的三样**：特权信息（→ 无教师 RL / DAgger）、加速（→ RL 不实用）、外部 reward（→ 无打分点）。这直接决定学习以**模仿 + 自监督 + affordance 校准**为主。

**失败样本不能省。** 只留成功轨迹，系统在没见过的失败状态上没有任何先验。

### 12.2 轨迹 schema

```
episode/
  meta.json          # 场景 ID、种子、起止时间、结果、数据版本
  obs/
    frames.idx       # 帧索引：时间戳、文件偏移
  actions.npy        # 动作序列
  skills.jsonl       # 技能调用与结果
  memory_diff.jsonl  # 本次 episode 造成的记忆变更
```

### 12.3 存储与压缩

**双目视频是最大的存储负担，必须先算账再开跑。**

以 640×480 双目 @ 30 Hz 估算：

| 形式 | 单帧 | 每小时 |
|---|---|---|
| 原始未压缩 | 640×480×3×2 ≈ 1.84 MB | **≈ 200 GB** |
| 有损视频压缩（50–100×） | — | **≈ 2–4 GB** |

结论：**必须用有损视频编码分片存储**，按 episode 切分，训练时懒加载 + 预取。不要存原始 PNG。

### 12.4 版本管理与可复现

每次训练必须记录：

- 数据集版本号 + 内容 hash
- 采集代码版本（commit）
- 场景集版本
- 随机种子

**训练必须可复现。** 不可复现的模型在出问题时无法定位，等于把调试能力丢掉了。

## 13. 开放世界设计

### 13.1 场景集

至少三层评测集：

| 层级 | 用途 |
|---|---|
| 训练场景 | 采集训练数据 |
| 同分布留出 | 常规评测 |
| 跨分布留出 | 泛化评测（**最重要**） |

多样性维度：布局、材质、光照、物体类别、房间连通性。

场景集必须**版本化**，并与数据版本绑定。

### 13.2 世界动态性

先回答一个问题：**世界会变吗？物体会被移动吗？**

- 会 → 记忆必须支持失效与重新观测（靠 `last_seen` + `confidence`）
- 不会 → 可以做更强的缓存

这个决定影响记忆层的复杂度，必须在 M0 阶段定下来。

### 13.3 视野外一致性

- 离开视野的实体**保留但降低 confidence**，不要立即删除
- 重新进入视野时做一致性校验；位置变了就更新 + 记一条事件
- 这是防"地图漂移"和"记忆冲突"的关键机制

### 13.4 探索终止与重置

| 情况 | 处理 |
|---|---|
| 单次运行时长 | 设上限，到点优雅收尾 |
| 卡死检测 | 换区域 / 重新搜索 |
| 全局重置 | 清空记忆，**但保留技能库** |

> 最后一条很关键：**技能库是跨 episode 的资产**，重置时绝不能清掉。这是系统"越跑越强"的唯一载体。

## 14. 部署形态与资源

> 原计划缺失。部署形态直接决定延迟预算（见 §15）和通信设计。

### 14.1 部署形态

| 形态 | 适用 | 说明 |
|---|---|---|
| 本地单机多卡 | 训练 | 仿真 + 训练，Isaac Lab 需 GPU |
| 本地推理机 | 运行 | 控制层本地低延迟；决策层可远程调 LLM |
| **混合（推荐）** | 运行 | 执行 / 技能 / 记忆本地；LLM 走 API |

### 14.2 硬件分层需求

| 角色 | 需求 |
|---|---|
| 训练机 | 多卡 GPU，大显存（仿真并行 + 训练） |
| 推理机 | 单卡即可；控制层模型小 |
| 运行机 | CPU + 可选 GPU；依赖 LLM API 时需联网 |
| 存储 | 高速 SSD（轨迹写入）+ 大容量冷存（数据集） |

### 14.3 通信中间件

多模块跨进程 → 需要消息总线。候选：

- ROS2：生态好，适合机器人
- gRPC：简洁，跨语言
- 自研 ring buffer：最低延迟

**约束**：控制层 ↔ 仿真/机体之间建议**零拷贝共享内存，不要走网络**。跨网络会直接吃掉 §15 的延迟预算。

## 15. 推理延迟预算与优化

> 原计划缺失。不先定预算，控制层频率（10–100 Hz）根本保不住。

### 15.1 每层延迟预算

| 环节 | 预算 | 备注 |
|---|---|---|
| 相机采集 | ~1 帧 | — |
| **控制层前向** | **≤ 30 ms** | 才有余量跑 30–100 Hz |
| 技能层查询 | ≤ 100 ms | — |
| 记忆检索 | ≤ 200 ms | 在决策循环里，不能更慢 |
| 决策层 LLM | 1–10 s | 异步，不占关键路径 |

**控制层是唯一的硬实时环节。** 若前向超预算，处理顺序：降分辨率 → 量化 → 蒸馏更小模型 → 降控制频率（最后手段）。

### 15.2 优化手段

- 导出 ONNX / TensorRT，FP16 起步，必要时 INT8
- 图像预处理放 GPU，别在 CPU 上做
- 视觉骨干与动作头分离：骨干低频、动作头高频
- LLM 侧：prompt 缓存 + 小模型初筛 + 结构化输出减少重试

### 15.3 测量方法

**端到端打点**（采集 → 动作），不是只测网络前向。真实瓶颈常常在预处理和进程间传输，只测前向会得出错误结论。

## 16. 软件工程与测试

> 原计划只有"回归测试"一句。多模块系统没有工程规范，第三周就没人敢改代码。

### 16.1 仓库结构（建议）

```
repo/
  contracts/       # 四份 schema + 校验器 + 版本
  sim/             # 仿真接入、场景生成、脚本专家
  perception/      # 深度、检测分割、位姿、标定
  memory/          # 三级记忆、检索、反思
  skill/           # 技能库、affordance 模型、代码沙箱
  policy/          # （可选）控制策略模型、训练、导出
  runtime/         # 状态机、调度、看门狗、回放
  agent/           # 决策层、prompt、上下文组装
  eval/            # 评测流水线、回归测试、裁判
  tools/           # 回放器、token 账本、记忆浏览器
```

### 16.2 规范

- 语言/风格：训练用 Python；运行时热点可 C++ / Rust。统一格式化 + lint 进 CI
- 配置：一切超参进配置文件（YAML），禁止硬编码；配置随实验版本化
- 日志：结构化日志（JSON），每条带 `episode_id` + 时间戳，可追到帧
- 版本：代码 commit + 数据版本 + 场景版本 + 模型版本四者绑定，一次实验一个 manifest

### 16.3 代码沙箱（代码即动作的前提）

技能层会让 LLM **写代码**并执行。必须有沙箱：

| 约束 | 内容 |
|---|---|
| 隔离 | 子进程 / 容器，无网络、无文件系统越权 |
| 超时 | 硬超时，超时即杀，记 `timeout` |
| 资源 | CPU / 内存上限 |
| 权限 | 只能调白名单里的技能原语与只读状态接口 |
| 留痕 | 生成的代码、输入、输出全部落盘，可回放审计 |

没有沙箱，"代码即动作"就是给 LLM 一个任意执行的后门。

### 16.4 CI/CD 与测试金字塔

| 阶段 | 内容 |
|---|---|
| 提交门禁 | lint + 单测 + schema 兼容性检查 |
| 每次改动 | 冒烟 rollout（短 episode，固定种子）+ 与基线回归对比 |
| 发布 | 模型导出 + 固化 manifest + 打 tag |

| 层级 | 对象 | 例子 |
|---|---|---|
| 单元 | 纯函数 | schema 校验、视差→深度、检索打分、标定变换 |
| 集成 | 模块边界 | 观测→动作全链路跑通；记忆读写事务 |
| 回放测试 | 确定性 | 固定观测序列 → 动作必须逐位复现 |
| E2E / 影子 | 真实运行 | 长跑健康度指标；消融对比 |
| 对抗 | 边界 | 缺帧、坏帧、LLM 超时、记忆冲突注入 |

**可复现是测试的前提**：固定种子 + 记录环境版本。回放测试是对抗"改 A 坏 B"最便宜的手段。

## 17. 安全与约束

| 约束 | 内容 |
|---|---|
| 动作限幅 | 摇杆幅值上限、头部角速度上限、加速度上限 |
| 参数校验 | LLM 输出的技能参数必须过 schema + 值域校验 |
| 越界保护 | 目标点必须在已知可通行区域内 |
| 不可变层 | 安全规则、身份锚点，每次决策强制生效，只读 |
| 紧急停止 | 看门狗 + 外部中断接口 |
| 速率限制 | LLM 调用频率上限，防止循环刷 prompt 烧钱 |

> 无人值守时这些是底线。LLM 提出"走进墙里"的计划是完全正常的事，不能指望它自己发现。

### 能力硬边界

**接触密集型任务做不到。** 没有力觉和触觉，插拔、拧紧、加压擦拭这类任务在观测预算上就是不可能的。任务设计必须避开这一类，这不是工程问题，是物理限制。

## 18. 失败检测与降级

无目标系统不会"失败得轰轰烈烈"，它会**安静地变成一坨**。所以检测和降级必须成对接地设计。

| 故障 | 检测方式 | 降级策略 |
|---|---|---|
| 循环卡死 | 状态哈希重复 + 动作重复计数 | 中断技能，标记失败，换区域 |
| 目标漂移 | 意图栈与当前行为不一致 | 重新加载意图，让 LLM 重新规划 |
| 记忆幻觉 | 写入缺 provenance | 预防性拒绝写入 |
| 动作退化 | 动作熵 < 阈值 | 强制注入探索 |
| 上下文爆炸 | 记忆条目数 / token 数超限 | 强制触发反思压缩 |
| LLM 不可用 | 调用超时 / 报错 | 降级到缓存技能序列 + 纯探索模式 |
| 感知失效 | 视差置信度低 | 降速 / 停等，切换单目先验 |
| 位置漂移 | 回环重定位残差大 | 触发重定位，暂停当前任务 |
| **位姿失效（掉坑 / 传送）** | 自由落体（速度持续向下）、位姿跳变、跟踪丢失 | 进入 `LOST` → 开新子图，用视觉地点识别尝试重连；接不上就当新地图继续（§2.5） |

**五个必须持续监控的退化指标**（比任何模型指标都直观）：

- **动作熵**——掉到接近 0 就是退化成单一行为，这是最早的警报
- **卡死率 / 循环率**——最容易恶化，也最容易被忽略
- **空间覆盖率**——上升即可，不必到 100%
- **技能库大小**——单调上升，后期自然饱和
- **自提目标完成率**——波动上升

### 四个直观的行为信号

- **主动好奇**：往没去过的地方走，而不是在熟悉区域打转
- **回头看**：走过一个房间后会转头发看身后——这是主动视觉长出来的直接证据
- **失败换招**：同一动作失败两三次后会换方法，而不是重复几十次
- **言行一致**：说要做什么，轨迹真的朝那个方向

## 19. 评测基建

### 19.1 评测流水线

| 组件 | 要求 |
|---|---|
| 场景集划分 | train / val / test 三层，含跨分布 |
| 批量 rollout | 自动化、固定随机种子、固定步数、可并行 |
| **回归测试** | 每次改动跑固定评测集，与基线对比 |
| 消融框架 | 去双目 / 去速度 / 去朝向 / 去记忆 / 去技能库 |
| LLM 裁判 | 固定模型版本 + 人工抽样校准 |

> **回归测试是最容易被跳过、也最致命的一环。** 你改了记忆模块，怎么知道控制层没跟着退化？没有回归测试的多模块系统，改到第三周就没人敢动代码了。

### 19.2 评测指标（无打分点时用什么替代）

| 维度 | 指标 |
|---|---|
| 技能可行性 | affordance 预测成功率与**实际**成功率的相关性 |
| 行为分布 | 覆盖率、轨迹簇数、动作熵 |
| 自洽性 | 自述意图与执行行为的一致率 |
| 长程 | 自提目标的完成率 |
| 健康度 | 卡死率、循环率、无效动作占比 |
| 主观 | LLM-as-judge 对轨迹自然度打分 |

**LLM 裁判的坑**：前沿评审模型之间差距其实很小，而且不同裁判的严格程度不同（同一批轨迹，有的裁判认为 A 更强，有的认为 B 更强）。所以——**裁判模型版本必须锁死**，并且必须做人工抽样校准，否则你测的是裁判的偏好而不是系统的能力。

**自洽性最值得投入**：它直接暴露"LLM 只在讲故事，控制层根本没照做"这类断裂，这是分层 Agent 最典型的隐性故障。

## 20. 成本预算

三块硬成本，**不先算这笔账，方案可能在第一周就破产**。

### 20.1 环境运行成本（不再是仿真算力）

本项目的分布来源是**真实客户端离线实例**（§11.1），不是仿真，成本模型随之改变：

```
成本 = N 个真实客户端 × 24/7 运行（电 + 机器 + 账号 + 渲染 GPU）
```

- 关键问题不是"能不能跑 RL"，而是 **N 要多大才够**——它决定你是"模仿为主"还是"真能跑 RL"（§11.1）。
- 真实客户端通常只能 **1x 实时、不能加速** → 每样本比仿真贵 2–3 个数量级，这笔账 M0 就要算清。
- 仿真**可选，非必需**：真实客户端已是唯一且最优的分布来源，重建视觉匹配的仿真是高成本低收益。

（若将来启用 §11.2 的控制层策略训练，成本另按 `GPU 小时 = 并行环境数 × 训练步数 ÷ (每 GPU 每秒步数) ÷ 3600` 计算。）

### 20.2 LLM token（最容易被低估）

按每次决策 8k 输入 + 1k 输出、决策频率 0.2 Hz 估算：

| 项 | 数值 |
|---|---|
| 单次调用 | ~9k token |
| 每小时调用 | ~720 次 |
| 每小时 token | **~6.5 M** |
| 8 小时运行 | **~52 M token** |

这还只是**单次运行**。开发期每天的调试运行会叠加数倍。**必须配 token 账本监控 + 速率限制。**

### 20.3 存储

双目视频压缩后约 **2–4 GB / 小时**。训练集规模 × 小时数 × 多版本备份，这是持续成本。

## 21. 里程碑与验收标准

| 里程碑 | 产出 | 验收标准 | 依赖 |
|---|---|---|---|
| **M0** 契约·标定·环境 | 四份 schema + 标定完成 + 仿真接口 + 脚本专家 + CI/单测 | 脚本专家能跑通；schema 有校验器 + 单测；标定表全部填完 | — |
| **M1** 几何与状态估计 | 深度 + 位姿 + 置信度 + 自我模型 | 与真值对比：姿态误差、平移漂移率达标；`self_pose` 可用 | M0 |
| **M2** 记忆 v1 | 三级记忆 + 检索 + 冷启动预热 | 重复进入同一场景的探索时间显著下降 | M1 |
| **M3** 语义层 + 控制层 | 增量语义地图 + 闭环伺服对准 | 语义标注位置与实际对得上；能走到交互位姿并对准目标 | M1 |
| **M4** 技能层 | 技能库 + affordance 模型 + 代码沙箱 | 技能复用率；affordance 预测与实际相关性；沙箱逃逸测试通过 | M3 |
| **M5** 运行时 | 状态机 + 看门狗 + 回放 + 部署/延迟达标 | 连续跑 N 小时不崩；故障可完整回放；控制层前向 ≤ 预算 | M0 |
| **M6** 决策层接入 | LLM 规划闭环 + 目标生成 | 自提目标完成率；卡死率达标 | M4, M5 |
| **M7** 长跑调优 | 稳定性打磨 | 连续运行 8 小时，行为指标不衰减 | M6 |

**关键路径提醒**：**M5（运行时）应与 M1–M4 并行推进**，因为它不依赖任何模型。很多人把它排到最后，结果所有模块都写完才发现跑不起来。

### 分阶段你能亲眼看到什么

| 阶段 | 观察到的现象 |
|---|---|
| M1 | 给定目标点能稳定走过去、停下来、转头对准 |
| M2 | 能回答"上次那个箱子在哪"；重复场景探索时间下降 |
| M3 | 语义地图上能认出物体；能走到开关前并伸手对准 |
| M4 | 技能库从 0 涨到几十个；新任务靠已有技能组合完成 |
| M6 | 无人干预连续运行数小时；自己提的目标被自己完成 |

## 23. 不该期待什么

这部分比上面都重要，写在这里防止预期错位：

- **不会有"通用智能"。** 它不会做人能做的所有事，也不"理解"这个世界。
- **接触密集型任务做不到。** 没有力觉和触觉，这是硬边界。
- **不会零样本工作。** 语义与 affordance 仍需在真实场景中积累观测；只是不必在仿真里采动作样本。
- **不会自己发明技能库以外的能力。** 技能库定义能力上界；用"代码即动作"能靠组合长出新行为，但超不出原语的物理极限。
- **做不到无人值守跑几天。** 会漂移、会卡死、会记忆污染，必须定期重启和人工审计。
- **LLM 的常识 ≠ 世界的常识。** 它会一本正经地提出物理上做不到的计划，affordance 模型就是专门拦这个的。

### 预期效果的正确表述

不是"造出一个会自己做事的 AI"，而是：

> **得到一个能连续跑数小时、自主积累几十个技能、记得住自己去过哪见过什么、失败后会换招、而且你随时能说清它此刻为什么这么做**的运行时。

如果验收标准里没有"能说清它为什么这么做"这一条，这个项目最终会变成一个没人敢动的黑盒。

### 确定性产出是三个副产品

1. **一个能持续积累的技能库**——可量化、可复用、可迁移的资产
2. **一套被可用性验证过的具身记忆系统**——这块在整个领域里都还稀缺
3. **一个能量产评测数据的运行环境**——无目标的开放世界本身就是最稀缺的数据源

"智能体本身"反而是最不确定的那一个。

### 三组容易混淆的概念

**(1) VLM ≠ VLA**

| | 输入 | 输出 | 本项目 |
|---|---|---|---|
| VLM | 图像 + 文字 | **文字** | **用**：看懂画面、说清场景 |
| VLA | 图像 + 文字 | **动作**（端到端策略） | **不用**（见 §2.1 / §10.2） |

**(2) 动作专家 / 策略 ≠ 运动生成器 / 先验**

| | 本质 | 输出 | 开环 / 闭环 |
|---|---|---|---|
| 动作专家（策略） | 观测 → 指令 | 控制指令 | **闭环** |
| 运动生成器（ARDY 类） | 目标 → 动作 | 人体运动序列 | **开环** |

想找"动作专家"，该看 π0 / LingBot 里的 action expert，或真机上的跟踪策略（SONIC 类），**不是** ARDY。ARDY 这类是**运动生成器**，不是策略。

**(3) 位姿控制器**

游戏里 avatar 由引擎驱动，**不需要物理跟踪策略**：移动与转向由位姿控制器直接给速度 / 朝向指令。这是本项目**控制层**的组件。
