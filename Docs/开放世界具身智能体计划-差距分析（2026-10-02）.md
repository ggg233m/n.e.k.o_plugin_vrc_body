## 四、计划与项目已定裁决的冲突/需调和点

1. **语义层怎么建**：计划 §7.2 要"每个体素挂 CLIP/SigLIP 特征"；本项目实测"语义地标判别力 0"、类别判别已证伪，唯一活口是 **OCR 招牌文字**。两者不矛盾（计划语义层用于物体交互记忆，不是重定位），但落地时语义嵌入只该挂实体节点，**别再试图拿语义做地点识别**。
2. **选型表过不了许可门**：计划 §10.1 提的 YOLO-World（Ultralytics 包装）= AGPL 出局 → 用 Grounding DINO / RF-DETR 等 Apache-2.0；§7.1 的 RAFT-Stereo/FoundationStereo 过不了 A770 的 CUDA/许可门 → 自写 SGBM 继续当主力。计划的技术栈必须先过项目的许可过滤器，但也许可以靠做成独立模块规避。
3. **wander_step 与"LLM 不进控制回路"的张力**：现在 LLM 逐步选 left/forward/right，频率虽低但粒度是控制级的；计划要求 LLM 只发 `SkillCall`。迁移方向明确：把 wander 收敛成带 postcondition 的技能，LLM 退到出发前决策。
4. **社交维度计划完全没写**：项目北极星含"站着聊天、跟着人走、被搭话转过去"（ReID、avatar_identity、社交唤醒已在做），这部分是项目**领先计划**的地方，不需要削足适履。
5. **计划 §11.2 RL/仿真/特权教师**：本项目早已判死（无打分点、真实客户端 1x），与计划 §11.1 边界判定一致——**不用做，这是共识不是缺口**。

## 五、距离的量化表述与建议顺序

- **整体粗估 30–40%**：底层（控制/几何/异步调度/评估方法论）扎实，上层（记忆/语义/技能/目标生成）未起。
- 项目 ROADMAP 的 P0（跨会话重定位）与 P1（LLM 地图工具）**恰好就是计划 M1 尾巴 + M2/M3 的最小对外接口**——两条路线图不冲突，计划反而验证了当前排序。
- 在 P0/P1 之后，按计划补齐的增量顺序建议：
  1. **技能 schema + postcondition**（打分点是唯一学习信号，M4 的地基，且便宜——纯接口工程）
  2. **摇杆逐轴标定成文 + 看门狗/状态机**（M0/M5 补课，都是几天的活）
  3. **语义层最小版**：检测器加深度（apparent_height→米）+ OCR 通道，先支撑"实体级记忆"而不是体素 CLIP
  4. **affordance 查表版**（先查表后训练，计划 §10.1 原话）
  5. 目标生成（§8）放最后——它依赖技能成败记录存在才有意义
- 一句话：**从计划视角看，项目已经把"骨架"浇筑完，且比计划更早证伪了几条死路；剩下的是计划里最值钱也最没做的那三层——记忆、语义、技能。**
