# G1 实测：延迟过了，占用没测出来（2026-11-02）

> 方案 §1 的 G1 门是三条：**p95 ≤ 200 ms**、**p99 ≤ 300 ms**（= 块丢弃率 ≤ 1%）、
> **GPU 总占用 < 90%**。本文把前两条测了，第三条**没测成**，原因写在最后。

## 一、结论

| 配置 | p50 | p95 | p99 | p95 门 | p99 门 |
|---|---|---|---|---|---|
| compile（无图） | 279.6 | **293.0** | 303.5 | ❌ | ❌ |
| **图重放（XPUGraph 双图）** | 118.3 | **123.4** | **125.8** | ✅ | ✅ |
| **图重放 + LAS2 并发 + VRChat** | 157.8 | **175.8** | **179.9** | ✅ | ✅ |

单位 ms，448×256，真机 1080×606 原始帧，1 Hz 生产节拍。

**图重放是 448×256 唯一能过 G1 的路。** 不开图 p95 293 ms，超门 1.47 倍；
开图 123 ms，离线余量 38%，并发下 176 ms，余量 12%。

这同时**否定了方案 §1 的降级顺序**。§1 预登记的是「① 1 Hz → ② 双图重放 → ③ 回 224² 重训」，
按外推 204–262 ms 写的。实测 293 ms 说明外推偏乐观，但**降级 ②（图重放）不需要先走降级 ①**：
它直接让 1 Hz 都过不了的门变成 2 Hz 也过（123 ms × 2 Hz = 24.6% 占用）。
真正该做的是把图重放从「降级备选」提为**生产默认**。

## 二、图重放算的是同一件事

`cos_min = 0.99995`（12 拍，图重放 vs eager 逐拍比动作块），过方案 §6.1 的 0.999 门。
最大逐元素差 0.036 m/s。**必须先有这条，否则「123 ms 过门」只是在给一个错答案掐表。**

计数器也对得上：`replays=230, fallbacks=0`（200 次计时 + 30 次预热）。
图没有被静默回退到 eager —— 这一点如果没查，123 ms 可能是 eager 恰好跑快了。

## 三、并发口径

- LAS2 走 `make_stereo_backend(subprocess=True)`，与 nav_online 同一工厂、同一个 `.venv_las`
  子进程、同一套 SHM+信号量；
- 首帧 75.1 s（冷编译），之后 2766 帧 / 180 s ≈ **15.4 Hz**，p50 62.8 / p95 86.8 ms，0 错误；
- VRChat 全程在跑（pid 13152）；
- 策略按 1 Hz 节拍跑 180 拍。

并发让 p50 从 118 → 158 ms（+34%），p99 从 126 → 180 ms（+43%）。
**涨幅真实但没破门**，余量从 38% 压到 12%。

## 四、没测成的：GPU 总占用

`gpu_lt_90: false` 这个字段**不可信，不要引用**。原因：

Windows 的 `\\GPU Engine(*)\\Utilization Percentage` 是**按「进程 × 引擎」**报的。
一块 A770 上 VRChat 在 `engtype_3d`、LAS2 在 `engtype_compute`、策略在 `engtype_compute`，
三类可以同时忙，求和天然超过 100% —— 实测 **109%（p50）/ 113.6%（max）**。
拿它去比方案里那个「总占用 < 90%」是跨口径比较，那个 90% 的分母是整卡时间片。

要真测需要 `xpu-smi`（本机没有）或 Intel GPA。**这一条仍然空着，G1 不能算全过。**

顺带记三个踩过的坑，都让结果恒为 0%、看起来像「GPU 空闲」：
1. 计数器名是 `engtype_3D`（大写 D），小写比较才对得上；
2. **LAS2 跑在 Compute 引擎**，只取 3D 会完全看不见它那 83%；
3. typeperf 的 CSV **只有一行表头**，按两行写会把第一行数据当表头。

## 六、对方案的影响

1. §1 降级顺序 ①②③ 要重排：**图重放从 ② 提到默认**，① 1 Hz 不再需要（2 Hz 就够）。
   1 Hz 现在只是「图捕获失败时的兜底」。
2. §1 的预算表 448×256 行要按实测重写：不是「外推 99–107%」，而是
   **离线 24.6% / 并发 35.2%**（按 p95 × 2 Hz 加同场基线，基线待 xpu-smi）。
3. 图重放的**启动成本**要写进 M0：实测 setup 79 s（其中双图捕获 4.1 s，其余是 compile + 预热）。
4. G1 仍差「GPU 总占用」这一条，需要先解决工具问题。
