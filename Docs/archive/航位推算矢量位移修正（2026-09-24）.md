## 一、Bug

`OscPath` 的 `VelocityX/Z` 是 **avatar 本地坐标系**（README 已实机验证：
"`VelocityX/Z` 是 avatar 本地坐标系——转 90° 后仍是 Z 主导，因此 `velocity_z` 直接就是前进分量"）。
所以 avatar 本地位移是一个**矢量**，必须保留方向、再按朝向旋进世界。

| 实现 | 做法 | 对横移 |
|---|---|---|
| `backend/online_pose.py` `OnlinePose2D` | `x += vx·cos(y) + vz·sin(y)`；`z += -vx·sin(y) + vz·cos(y)` | ✅ 正确 |
| `.slam_probe/.../pose_graph.py` `dead_reckon` | `ds = osc.dist(...)`（= ∫\|v\|dt，**标量**）然后 `x += ds·sin(y)` | ❌ **把横移当成前进** |

`dead_reckon` 只在 `vx ≈ 0` 时与在线式等价。同一物理量在两处被两种方式积分，其中一种是另一种的退化特例。

**为什么现在才重要**：`Docs/世界模型导航方案-可行性评估.md:2518` 明确要用
「撞墙**横移绕行**（`/input/Horizontal`，不改朝向故不依赖转角精度）」。
LLM 控制场景下横移会被**有意、更频繁地使用**。

### 顺带修正两处**已失效的推理依据**

`pose_graph.py` 里有三处硬编码论断：「闭环对 ±yaw **镜像对称**，挑不出符号」。
这在**标量模型**下成立（翻符号 = 沿 x 反射，闭环误差不变，实测差 0.000000）。
改用矢量位移后**只在 `dvx == 0`（无横移）时才成立** —— 本 run 实测 ± 差 **1.977447 m**。
已改：CLI help、符号来源注释、`sign_note`、验收逐条 §1 对照。措辞改为按 `closure_gap`
分支：接近时说明"镜像对称、挑不出符号"，可分辨时说明"已可分辨，但闭环比对是内部自洽性、不作外部参照"。

**两点解读**：

1. **DR 端点差 1.56 m，但地图节点只动 ≤0.69 m** —— 13 条回环边把一部分偏差吸收掉了。
   所以「地图本来就有问题」成立，**但幅度被回环部分掩盖**：改前的闭环前漂移比改后**大 30%**。
2. **「前进方向自洽比例」从 86.2% 掉到 80.1% 是预期行为，不是回归**：
   该指标衡量"这一步是否沿朝向走"，而矢量模型下轨迹**合法地**含有横移步。
