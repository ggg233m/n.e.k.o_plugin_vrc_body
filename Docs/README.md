# Docs 索引与权威性（先读这份）

> **硬规则**：读 `Docs/` 下任何文档之前，先读本文。
> **当前值一律查 [`FACTS.md`](FACTS.md)** —— 它是唯一真值单源；
> 文档之间**存在互相冲突的陈述**（33 组 = C1–C23 + C33 详版 + C24–C32 归档，见 [`CONFLICTS.md`](CONFLICTS.md)），
> 而多数文档是**日期化的实验记录**，它们描述的是**当时**的代码，不保证描述**现在**的代码。
>
> **冲突时的优先级（自上而下，先命中先赢）**：
> 1. **[`FACTS.md`](FACTS.md)** —— 当前值唯一真源（常量 / 结论 / 状态）
> 2. **本文 §二 权威矩阵** —— 每个主题只认一个权威
> 3. **`ROADMAP.md`**（根目录） —— 方向与能力现状
> 4. **`Docs/文档勘误与过时清单（2026-09-29）.md`** —— 旧路径→现状映射、已证伪的断言
> 5. **代码本身** —— 最终真值。任何文档与代码不符，**以代码为准**
> 6. 日期化实验报告 —— 只在其**标明的日期与代码状态**下有效
>
> **给 agent 的具体动作**：本仓库的文档**不能当作"当前实现"来引用**。
> 断言"现在有/没有 X"之前，先查 [`FACTS.md`](FACTS.md) 与 [`CONFLICTS.md`](CONFLICTS.md)，再查代码。

| 层 | 位置 | 怎么搜 |
|---|---|---|

| **历史层** | `Docs/archive/`（36 份） | `rg <关键词> Docs/archive/` —— 只搜历史（显式给路径即可） |

`Docs/.ignore` 让 ripgrep 默认跳过 `Docs/archive/`（**不影响 git 追踪**）。
三种用法实测均正常：

```bash

rg <关键词> Docs/ -u         # 全量（现役 + 历史）
rg <关键词> Docs/archive/    # 只搜历史
```

> ⚠️ `.ignore` 里必须写**目录通配** `archive/`，不要写逐文件清单 ——
> 逐文件模式相对 `Docs/` 解析，**显式指定 `Docs/archive/` 时文件级忽略仍生效**，
> 会把"只搜历史"变成 0 命中（2026-10-08 实测踩到）。

## 四、维护规矩（防止再次互相冲突）

1. **新文档必须自带状态与日期**：标题或首段写明"这是**现状**还是**某日的快照**"。
2. **改结论时改源头，不要只在新文档里说**：若某份旧文档的结论被取代，
   在 [`CONFLICTS.md`](CONFLICTS.md) **加一行冲突登记**，而不是只在新文档里写。
3. **不要在文档里写"当前有/没有 X"**：换成指向代码的写法
   （例如"见 `tool_defs.py`"），或者加**条件句**（C2 的教训：
   一刀切断言在两个方向上都会变成伪造）。
4. **清理一个断言时，搜索范围要覆盖全部文件类型**（`*.py` + `*.md` + `*.toml`）
   —— C2 第一次修复漏了 `README.md`，就是因为只搜了 `*.py`。
5. **动笔前先查本仓库是否已经规定过改法** —— C2 第一次改错了方向，
   而正确的改法早在 `可行性评估.md`（**现为 `:214`**，原写 `:179`）写明。
6. **提交前跑两条门禁**：`python research/tools/doc_health.py`（markdown 结构完整性，
   已登记项不计入失败）与 `python research/tools/import_audit.py`（发行面跨根依赖）。
   加 `--refs` 可看引用存在性的**候选清单**（历史报告合法引用旧路径，故不作门禁）。
7. **🆕 新增文档必须同时登记进 §三**，且**表里引用的文件必须真实存在**。
   2026-09-30 → 10-04 之间新增了 11 份文档、**一份都没进 §三**，
   而 §三 表头还写着「32 份」、并登记了一份**已被删除**的文件 ——
   结果是「读本文再读文档」这条硬规则对 **28%** 的文档失效。
8. **🆕 门禁只查结构，查不出语义。** `doc_health.py` 的硬门禁是
   `**` 配平 / `。。` / 链接里的 ASCII 括号；**引用存在性只是 `--refs` 软报告，
   语义陈旧（计数、状态、"当前有/没有 X"）完全不在检查范围** ——
   上面第 7 条的漏登记就是它一条告警都没触发的原因。
   **新增文档时请顺手核一次 §三 的份数**，或给 `doc_health.py` 加一条
   "§三 登记项 vs `Docs/*.md` 实际集合"的差集检查。
9. **🆕 别把「代码默认」写成「默认」**（C19）。`config.py` 是代码默认值、
   `plugin.toml` 是发行值，同一个键可以有两个值。
   `backend/README.md` 的习惯是对的（`capture = "desktop_mirror" # 随插件部署的 plugin.toml 用 wgc`），
   根 `README.md` 照抄这个习惯。
10. **🆕 没有实测、没有仓库引用的文档，必须在**文首**声明性质。**
    规矩 1 要求的是"自带状态与日期"，但**只写在 §三 索引里不够** ——
    agent 通常直接 `open Docs/xxx.md`，不会先翻索引。
    判据很简单：全文检索 `ROADMAP` / `backend/` / `实测` / 任何日期，
    **零命中就说明它不是本项目的实测产物**，必须在文首写明（参考
    `开放世界具身智能体-项目计划.md` 的抬头）。这类文档归 📑「外部调研 / 参考」，
    **不是 📊「数据有效」** —— 后者意味着"数字是真的"，前者只意味着"这是个有用的参照"。
