# Docs 索引与权威性（先读这份）

> **硬规则**：读 `Docs/` 下任何文档之前，先读本文。
> 文档之间**存在互相冲突的陈述**（共 **21 组**，见 §三），而多数文档是**日期化的实验记录**，
> 它们描述的是**当时**的代码，不保证描述**现在**的代码。
>
> **冲突时的优先级（自上而下，先命中先赢）**：
> 1. **本文 §二 权威矩阵** —— 每个主题只认一个权威
> 2. **`ROADMAP.md`**（根目录） —— 方向与能力现状
> 3. **`Docs/文档勘误与过时清单（2026-09-29）.md`** —— 旧路径→现状映射、已证伪的断言
> 4. **代码本身** —— 最终真值。任何文档与代码不符，**以代码为准**
> 5. 日期化实验报告 —— 只在其**标明的日期与代码状态**下有效
>
> **给 agent 的具体动作**：本仓库的文档**不能当作"当前实现"来引用**。
> 断言"现在有/没有 X"之前，先查 §三 冲突表，再查代码。

### C6 —— 内参 102.45° vs 121.3°（**这不是矛盾**）

| 值 | 属于 |
|---|---|
| **102.45°**（fx=385.61@960×540） | **OBS 视频 / 桌面窗口**路径，由正交性自标定 |
| **121.3°**（fx=202.5@720×405） | **SteamVR 镜像**路径，由 `getProjectionRaw` 得出 |

➡ **两者都对，但属于不同采集路径。** 因为镜像视口是**整张纹理经 mip 整数降采样**得到的
（无裁剪、无非等比缩放），半角正切覆盖整张纹理 ⇒ 任意 mip 下 `fx = W/(r−l)` 都成立。
⚠️ **但这是个耦合**：`config` 的 102.45° 被**在线**的检测器方位与可通行扇区消费。
**WGC 移除、画面换成镜像后，这个常数必须改由采集源推导**（`ROADMAP.md` P2）。
📌 把这条单列出来，是因为它**最容易被误读成"文档自相矛盾"**。
