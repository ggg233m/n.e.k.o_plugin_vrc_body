# 虚假障碍——根因、量化与分层修复（2026-10-05）

> 现象：面板上建出来的图"很差"，空地中间到处是障碍孤岛（截图：`/navmesh` 里大片白区里
> 撒满黑点），走过去点一下不动。目标：把**真结构**和**量化倾斜**分开。
> 结论：**不是阈值没调好，是 1.5 m 以外那一层深度信息本来就不存在**。改成按观测距离
> 分层判定后，走廊上的障碍格 044153 **2168 → 502（−77%）**、045615 **8737 → 3554（−59%）**。

## 一、根因：视差深度误差随距离平方增长，而障碍带只有 1.7 m 宽

面板口径 `镜像双目 720x405 fx 202.5 基线 0.126`，`range_m = 5.0`。
视差深度 `z = fx·b / d`，一像素视差误差对应的深度误差：

    δz = z² / (fx·b) · δd = z² / 25.5 · δd   （米）

| 距离 | 1 像素视差误差 ≈ |
|---|---|
| 1.5 m | 0.09 m |
| 3.0 m | 0.35 m |
| 5.0 m | 0.98 m |

而障碍高度带是 `ground_tol 0.30 … obst_top 2.0`，**宽 1.7 m**。

于是 1.5 m 以外"真地面被抖进障碍带"是**必然**的，不是阈值问题：
只要 1–2 像素的视差抖动，真地面的高度估计就会随机落进那条 1.7 m 宽的带子里。
`min_pts=3` / 3×3 多数 / `occ_ground_ratio=0.3` 只能**压密度**，补不回那一层根本不存在的信息。

这与项目自己两条旧记录是同一件事：

- `Docs/RTAB-Map双目评估（2026-09-26）.md:128`：1 像素视差的深度误差约 Z²/12.8，1.5 m 以外
  就会越过地面高度阈值，于是**每个观测扇形的外沿都有一圈假障碍**；
- `Docs/双目序列run5-7结论汇总（2026-09-27）.md:76`：3.0 m 处假障碍 38.73% → 4.72%
  （自建栅格替代 RTAB-Map 自带栅格的效果）。

`range_m=5.0` 意味着"远带"是 3–5 m，而**观测扇形的面积随半径平方增长**——外沿那一圈
恰好覆盖了整张图里最大的一块面积。所以假障碍不是零星几个点，是一大片。

## 二、这个修法其实早就做过，但没有接进在线侧

`Docs/离线多视角融合v1-假障碍清除（2026-10-02）.md` 记录了一次完整实验：把逐格计数按
**观测距离分带**（近 <1.5 m / 中 1.5–3 m / 远 >3 m），分类规则从"纯计数"升级为
"质量分层"，在 044153 上把环内已知障碍占比从 31.4% 压到 13.3%。

它**没有上线**，两个原因：

1. 实验脚本在 `.tmp/_fusion_v1.py`（草稿目录），文档"下一步"写的是把分类器输出落到
   world 先验 `navmesh_memory/<world>/prior/`——那件事没做；
2. 在线 mapper 其实**早就在算分带数据**了（`_acc_near`/`_acc_far`），但它只喂给覆盖度
   显示层，注释写得很直白："纯显示，不进三态判定"。**数据每帧都在算，算完扔掉。**

## 三、落地改动（`backend/nav_mapping.py`）

### 3.1 分带票（新增 4 个累加器，与 `_acc_g`/`_acc_o` 同布局同记账）

`_kf_base` 把原来只分"近看/远看"（`cov_near_m=3.0`，纯显示用）的两桶，扩成三桶：

| 累加器 | 含义 | 用途 |
|---|---|---|
| `_acc_on` | 障碍点，距离 < `q_near_m` | 近距定案 |
| `_acc_om` | 障碍点，`q_near_m` ≤ 距离 < `q_mid_m` | 中距确认 |
| `_acc_gn` | 地面点，距离 < `q_free_m` | 降级回空地的地板证据 |
| `_acc_omk` | 投过中距障碍票的**关键帧数**（每帧最多 +1） | 多帧一致性 |

`_acc_omk` 走的是和 `_acc_g` 完全一样的加减记账，`drop_points` / 回环挪位都能精确回退。

### 3.2 判定规则（`_by_quality`）

```
base = (n_o > min_pts) & (n_o >= occ_ground_ratio·n_g)，再过 3×3 多数   # 扁平口径，仍在算
occ  = base & ( 近带确认 | 中距确认 | 中距单帧例外 )
```

- **近带** `o_n > min_pts`：误差还在带边沿内，单帧即定案，**故意不带**地面压制条件
  （否则 `occ_ground_ratio` 会把真细障碍一起误杀）；
- **中距** `o_m > min_pts 且 o_mk ≥ q_mid_kf 且 O ≥ 0.3·G`：多帧一致 + 地面压制；
- **中距单帧例外** `o_m > min_pts 且 n_o ≥ q_solo_pts 且 远带票占比 ≤ q_far_tol`：
  "刚走近就看见了一堵墙"只会被一个关键帧看到，等第二个关键帧会把真墙误杀成 unknown。
  例外的闸门是**票干不干净**——远带票占比是这个场景里最能分开真结构与量化倾斜的一维；
- **远带没有定案权**。被否证的格降级：有 `q_free_m` 内的地面证据 ⇒ FREE，否则 ⇒ **UNK**。

### 3.3 两处顺带修掉的 bug

1. **降级被 FREE 吃掉**：`_by_quality` 返回的掩码是 uint8，而 numpy 把 uint8 数组当
   **整数下标**不是布尔掩码——`g[那个数组] = UNK` 实际一直在写第 0 行、第 1 行，一格都
   改不到还不报错。同一个 `uint8` 上做 `~` 还是按位取反（0→254），`rejected & ~restored`
   恒为 0。现在三个返回值一律真 bool。
2. **3×3 多数滤波的边界**：`cv2.filter2D` 默认 `BORDER_REFLECT_101`，会把图外沿的障碍格
   镜像回填，**边缘一圈白送 3×3 支撑**。改成 `BORDER_CONSTANT`（代价：图边缘的障碍格
   少一票支撑，`test_unmodelled_pitch_ground_tilt_is_fitted_out` 因此差 1 格，已放容差）。

### 3.4 配置面

`[navmesh.mapper]` 新增 `q_tiers`（关掉即回到改动前规则，便于现场 A/B）、`q_near_m`、
`q_mid_m`、`q_mid_kf`、`q_solo_pts`、`q_far_tol`、`q_free_m`。

## 六、怎么验的（两个工具，别手推）

- `tools/q_tier_ab.py` —— 把录制按事件顺序喂进**在线 `KeyframeGridMapper` 本体**再
  `rasterize()`，不另写一份分类器（离线实验固化的规则与在线实现漂移也无处藏）。

> 🔧 写这两个工具时踩到的坑，都写进注释了，别再踩：
> ① `NavGrid` 是**翻转过**的（`rasterize` 末尾 `g[::-1]`，行 0 是最大 y）。累加器映射回
> 栅格时漏掉这个翻转不会报错，只会让所有票型统计**上下镜像**，看着还挺像回事——
> 头一版就栽在这，自检"baseline 障碍格里 `n_o<=min_pts` 的比例"本该是 0 却打出 0.19。
> ② 别在别处重推 `lo_i`：用 `KeyframeGridMapper._grid_lo`（本次 `rasterize` 实际用的
> `(lx, ly)`），推错一次整张分析静默错位。

## 七、诚实的代价与边界

1. **可走面积几乎没涨**（044153 233.6 → 234.4 m²）。这不是没修好：走廊本来就是靠
   `walked` 撑着可走的，**卡住的是障碍格**（2168 → 502），障碍一清，路就通了。
2. **unknown 涨了**（044153 87674 → 97746）。降级的格一半落成 unknown——没有 1.5 m 内的
   地面证据就不许当 free（`nav_grid` 的红线"unknown 永不当 free"）。代价是图外那圈
   不会自动算作可探索区。想换回离线 v1 那种乐观口径：设 `q_free_m = 3.0`
   （044153 中心区 234.4 → 245.2 m²），代价是中距地面本身就是被抖出来的。
   **注意这两种口径的"走廊障碍"完全一样**（502），差别只在图外那圈。
3. **从没走近过的墙会降级**：只在 3 m 外被看到过、没进过中距的墙，现在按 UNK 算——
   不可走但也不挡路。想保守就把 `q_mid_m` 调大（代价是远带假障碍回来一部分）。
4. **改动的安全性依赖"真墙够密"**：中距单帧例外的闸门是 `n_o ≥ q_solo_pts`。
   又细又矮、只被一个关键帧看到一次的障碍仍可能被降级。现场换世界后**建议抽检一次**：
   看 `tools/q_tier_*.png` 那张前后对比图，黑色的"整块"如果是真的家具/墙，就调
   `q_solo_pts` 或 `q_far_tol`。
5. 离线 v1 的数字（31.4%→13.3%）与本文（18.67%→5.48%）**不可直接比**：v1 明确
   "baseline 与 fused 都不含 ray_clear"，而这里的在线管线含 ray_clear，起点就已经更低。
   两边测的都不是同一个东西，别拿它们互相验证。

## 八、建图效率：一次 1.5 秒的卡死（`tools/q_tier_bench.py`）

> 用户反馈"建图效率低"。面板上 `建图耗时 103 ms` 只是**每次**的量，漏掉了真正要命的东西。

按录制回放分阶段计时（397 次栅格化，391 关键帧，末图 163496 格），
**单次 p50 41 ms 看着不糟，p95 66 ms 也不糟——但最大值 1529 ms**。
建图循环 `map_min_interval_s = 0.3` 秒一跳，一次 1.5 秒的栅格化会把整条建图线程卡死 5 拍。

### 8.1 根因：`cam_h` 在两个值之间来回翻

`_update_cam_h` 按 1 cm 直方图取加权中位，超过 `cam_h_hyst_m` 就换——
**而换了要把所有关键帧重算一遍**（`_sync_acc` 走 `keys = set(self._pts)` 全量重建路径）。
实测 044153 回放里 cam_h 的历史值是：

```
1.765 → 1.745 → 1.765 → 1.745 → 1.765 → 1.745 → 1.765   共 9 次
```

每次翻转的代价随关键帧数线性涨：360 ms → 1450 ms。**9 次合计占全程栅格化时间 31%**。

两个原因叠在一起：

1. **滞回带取错了量级**。`cam_h_hyst_m = 0.02` 恰好卡在直方图相邻两桶的抖动幅度上；
   而且 `0.02` 这个比较在浮点上还不严格（`1.765 - 1.745 = 0.020000000000000018 > 0.02` 成立），
   滞回等于没生效。
2. **精度需求定错了**。`cam_h` 唯一的消费者是地面判定，而 `ground_tol_m = 0.30`——
   **1~2 cm 的精度纯属浪费**，给它配一条 2 cm 的滞回带，等于在噪声量级上反复横跳。

修法：滞回放宽到 6 cm（远大于桶噪声）、估计前先做与 `_ground_offset` 同一套 ±2 桶平滑、
再按当前规模限流（"距上次变更至少过了 `len(pts)//8` 个关键帧"），让重建次数 O(log N)、
总代价 O(N)。**cam_h 变更 9 次 → 0 次，单次最大 1529 → 62 ms。**

> 踩过的坑记在代码注释里：平滑后**分位必须用平滑后自己的总量**。5 桶卷积把直方图总和
> 放大约 5 倍，拿原始 `tot/2` 去搜等于在采 10% 分位——cam_h 一路从 1.756 漂到 1.465，
> 还顺带改坏了地面判定。限流也不能写成固定的"至少隔 40 个关键帧"，那会让头 40 帧的
> cam_h 永远停在默认值。

### 8.2 顺带两处等价优化（射线清除，`_ray_voxels`）

`_sync_ray` 修完 cam_h 后成了最大头（21.5 ms/次，占全程 54%）。两处改动，
都用**逐元素等价**验证过（300 组随机输入 + 25 帧真实关键帧输出完全一致）：

- `unique_rows`：用稠密标记数组代替 `np.unique` 的排序（关键帧体素都在 `range_m` 半径内，
  打包键跨度约 100×100×17）；**存下标 +1**——下标 0 与"这一格没被写过"在 0 初始化数组里
  一模一样，不加哨兵每个结果集都会漏掉第 0 行（300 组随机输入当场 300 组不一致）；
- `cells()`：一次 `np.empty` 写三列，代替 `column_stack` + `astype` 的两次整块拷贝。

### 8.3 结果

| 044153，397 次栅格化 | p50 | p95 | **最大** | 合计 |
|---|---|---|---|---|
| 修之前 | 41.3 ms | 65.8 ms | **1529 ms** | 23.5 s |
| 修之后 | 35.4 ms | 52.1 ms | **61.9 ms** | 14.3 s |

各阶段（修后，ms/次）：`_sync_ray` 17.6 · `_sync_acc` 7.2 · `_ray_veto` 4.9 ·
`_kf_base` 3.3 · `walked` 1.4。

**剩下的没再往下压**：`_ray_voxels` 15 ms 里，采样展开 1.3 ms、`cells()` 1.9 ms、
打包键 3.3 ms，其余 ~8.5 ms 在两次 `unique_rows` 的散写/扫描上。再改就要动"射线清除"
本身的语义（它决定障碍会不会被抹掉），风险收益不划算。

**质量没受影响**：044153 走廊障碍 2168 → 502、环内障碍% 18.67 → 5.48，改动前后一致。

## 九、高度分带：把被丢掉的那 29% 捡回来（`tools/band_report.py`）

> 起因：问「现在能建成 3D 空间吗」。审计判精确 3D 结案，但排查过程中发现一件更朴素的事——
> **头顶 2 m 以上的几何一直被整段扔掉**。

### 9.1 问题

分类器只认两段：`g = |h| ≤ ground_tol`（地面）、`o = ground_tol < h < obst_top_m`
（障碍，`obst_top_m = 2.0`）。`h ≥ 2.0` 的点**直接不参与任何判定**。

实测 044153（276 万抽样点）：

| 离地高度 | 点数占比 | 现状 |
|---|---|---|
| −1.0 ~ −0.3 m | 3.6% | 丢弃 |
| −0.3 ~ 0 m（地面）| 32.7% | 计入 |
| 0 ~ 2 m | 34.8% | 计入 |
| **2 ~ 3 m** | **7.0%** | 丢弃 |
| **3 ~ 5 m** | **20.9%** | 丢弃 |
| > 5 m | 0.8% | 丢弃 |

**28.7% 被丢掉**。在 VRChat 里 2 m 以上正是二楼、阳台、天桥、回廊和下层天花板——
系统对多层建筑是**结构性失明**，与精度无关。

### 9.2 为什么这不是 3D 重建

- 墙面平面误差实测 **0.059 m**（`tools/stereo_3d_audit.py`），avatar 半径 **0.25 m**，余量 4 倍。
  做**导航**够用；审计那条 0.07 m 止损线是为「视觉上正确的墙」设的。
- 位姿旋转是 HMD 绝对位姿的**逐位拷贝**（397 个关键帧 yaw/pitch/roll 修正量全部 `0.0000°`），
  **不存在旋转漂移**，无需投入。
- 平面性随融合帧数单调变差（2 帧 0.030 m → 391 帧 0.059 m），这是**平移**残差
  （回环修后平均 0.183 m）的累积，5 m 处折合 18 cm 横向位移。要 2 cm 就是 9× 工程。

### 9.3 落地（旁路产物，导航零变化）

新增 4 条带（h 的上界，追踪米）：`(-inf, −ground_tol]` / `(obst_top_m, hi_band_m]` /
`(hi_band_m, hi_band_top_m]` / `(hi_band_top_m, +inf)`，默认 3.5 / 6.0 m。
`h = rel_z + cam_h` 是**离地高**不是"离相机高"，跨关键帧可比。

**地面层一字未动**：`_acc_g`/`_acc_o`、质量分层规则、射线清除、三态栅格全部原样，
`HeightBandTests.test_ground_layer_is_bit_identical_with_and_without_bands` 逐格钉住。

### 9.4 这次**没有**做（别当成已交付）

带里存的是**点计数**，不是三态。计数 >0 只说明"那个高度看到过东西"，**楼板、天花板、横梁、
栏杆、桥面全都会落进去**。俯视图（`tools/band_*.png`）上 3.5~6 m 那片蓝色**多半是天花板和
观测扇形的外沿光晕，不是"找到了二楼"**——要区分得做带内高度聚类，本次没做，也没有数据支撑阈值。
