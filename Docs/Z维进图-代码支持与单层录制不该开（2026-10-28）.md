# Z 维进图：代码支持、导出 bug、与「单层录制不该开」的判据（2026-10-28）

> 接 `跨趟错位量级与来源（2026-10-28）.md` 与两位队友的报告（`.tmp/audit_report.md`、`.tmp/slam_survey.md`）。
> 本文记录：**把 z 加进位姿图**这件事从「想当然」到「实测变差」的全过程，
> 以及沿途挖出的一个真 bug 和一条可复用的判据。

## 〇、一句话结论

1. ✅ **z 测得准**：PnP 的相对平移本来就有完整三维，原先 `[:2]` 把它扔了。
   三元闭合残差竖直 **3.9–7.2 cm** vs 水平 4.8–8.6 cm，比值 **0.60–1.23**（4 个门槛下稳定）。
2. 🔴 **但这场录制开 z 会变差**：竖向叠层 p50 **14.00 → 22.40 cm（+60%）**。
   原因：玩家几乎没上下楼，z 的**真值本来就恒为 0**；19 条回环边撑 610 帧，等于把噪声放大成信号。
3. 🔴 **导出侧原来完全不读 `T[2,3]`**（`pointcloud_view.py:467` 注释「z 走地面高度口径」）。
   在 `T[2,3]` 恒 0 的年代自洽；z 有真值后这是个**静默丢弃**。已修。
4. **判据**：`|回环 z 边| 中位 < 3 cm ⇒ 该录制没有可估的 z，不要开 enable_z`。

## 一、为什么 z 原来不在图里

`backend/nav_loop.py` 的位姿图是**纯 2D 平移**（`_solve_laplacian` 里 `np.zeros((n,2))` + `range(2)`）。

这不是设计上的取舍，是**两处硬编码**：求解器只解 2 列，且 `_verify` 里 `(na.R @ t_ab)[:2]`
把 PnP 的竖直分量切掉了。

对照：**VINS-Mono 的先例是「roll/pitch 可观测 ⇒ 只砍 roll/pitch，保留 x,y,z,yaw」**。
我们朝向全部由 HMD 给定（连 yaw 都不用估），却**连 z 一起砍了**。
`_solve_laplacian` 的法方程是加权图拉普拉斯，与维数无关，`splu(...).solve(g)` 天然支持多右端项
⇒ 从 2 改到 3 只改一处循环。

## 二、改了什么（`backend/nav_loop.py`）

| 位置 | 改动 |
|---|---|
| `_solve_laplacian` | `np.zeros((n,2))`+`range(2)` → 按 `Z.shape[1]` 决定维数 |
| `_verify` | `(na.R @ t_ab)[:2]` → **保留完整三维**（核心）|
| `_Node` / `_Loop` | 加 `dr_z`；`z` 允许 2 或 3 列 |
| `optimize` | `.reshape(-1,2)` → `D` 维；两处 `np.hypot(*v)` → `np.linalg.norm` |
| `pose/offset/correct/correct_at` | z 只在 `enable_z` 时写，且用 **`dr_z`** 而非 `dr_xy[2]` |
| `LoopConfig.enable_z` | **默认 False** |

### 2.1 ⚠️ 三个必须记住的坑

1. **`np.hypot(*v)` 只接受 2 个参数**，三维时 `TypeError`。`_candidates` 的候选半径只关心水平，
   显式取 `[:2]`；`optimize` 的位移/残差用 `np.linalg.norm`。
2. **`offset()` 的 z 分量必须配 `dr_z`**，不能写成 `x[2] - dr_xy[2]`（`dr_xy` 只有 2 列，会 IndexError，
   或更糟：不小心广播成 `-x[2]`，整片点云上下翻转）。
3. **`optimize` 的 `D` 必须与 `Z` 的列数一致**：`.reshape(-1,2)` 在 z 存在时会**静默截断**。

### 2.2 默认路径逐位不变（已验证）

```
enable_z = False
回环 19 条（应 19）
与 final_poses 逐位比: 中位 0.000e+00 最大 0.000e+00
T[2,3]: abs max 0.000e+00
```

`tests/test_nav_online.py + test_nav_loop.py`：**124 passed**。

## 三、z 到底测不测得准

### 3.1 三元闭合（本文最关键的一张表）

对稠密三元组 `(k, k+1, k+2)`，比较 `t_ac` 与 `t_ab + R_ab·t_bc` 的残差，分水平/竖直两栏：

| `min_inliers` | 有效组 / 尝试 | 水平中位 | 竖直中位 | **比值** | 竖直 p90 |
|---|---|---|---|---|---|
| 50（原）| 22 / 608 | 4.81 cm | 5.94 cm | **1.23** | 26.5 |
| 25 | 48 / 608 | 6.53 cm | 3.91 cm | **0.60** | 21.9 |
| 15 | 62 / 608 | 6.93 cm | 4.60 cm | **0.66** | 23.5 |
| 10 | 74 / 608 | 8.57 cm | 7.17 cm | **0.84** | 28.3 |

**样本量放大 3.4 倍（22 → 74）后结论不变 ⇒ 排除了幸存者偏差。**

放宽门槛不引入错匹配：最大重投影 `1.08 → 1.20 px`（门限 3.0），最小内点中位 81 → 39。

⇒ **z 是可观测的，不是噪声。**

### 3.2 但「测得准」不等于「有用」

这 19 条回环的 z 分量（世界米）：

```
[-0.094, -0.094, -0.090, -0.030, -0.015, -0.013, -0.006, -0.003,
  0.002,  0.005,  0.012,  0.015,  0.015,  0.032,  0.067,  0.067,
  0.078,  0.184,  0.205]
```

|z| 中位 **0.030 m**、8/19 条 |z|>5 cm。**绝大多数集中在 ±0.03 —— 那就是噪声底**；
只有 +0.184/+0.205/−0.094 几条像真实高差，但只有 3–4 条。

🔴 **这场录制玩家基本在同一层平面走，z 的真值本来就恒为 0。**

## 四、实测：开了 z 反而变差

### 4.1 第一次导出「完全没变」——挖出一个真 bug

| 导出 | 竖向叠层 p50 | 面厚 p50 |
|---|---|---|
| `base`（无 z）| 14.00 cm | 3.39 cm |
| `zon`（`enable_z=True`）| **14.00 cm** | **3.40 cm** |

**一点没变。** 查源码发现（`pointcloud_view.py:466-468`）：

```
pw = p @ T[:3, :3].T                    # 只乘旋转
xy = pw[:, :2] + T[:2, 3]               # 平移只取 xy
zw = pw[:, 2] + cam_h - gc              # <- 完全没有 T[2,3]
```

**位姿图算出了 z（−0.10..+0.35 m，602/610 帧非零），导出把它整个丢了。**
在 `T[2,3]` 恒 0 的年代这是自洽的（加不加都一样），但一旦 z 有真值，这就是**静默丢弃**。

### 4.2 修掉后的实测

加了 `t_z = T[2,3]`、`zw = pw[:,2] + t_z + cam_h - gc`（`t_z=0` 时与老路径**逐位一致**）：

| 导出 | 格数 | 竖向叠层 p50 | p75 | p90 |
|---|---|---|---|---|
| `base` | 24587 | **14.00 cm** | 32.00 | 48.00 |
| `zon`（z 进图但导出未用）| 24596 | 14.00 cm | 32.00 | 48.00 |
| **`zon2`（z 真正生效）** | 23385 | **22.40 cm** | 36.00 | 46.00 |

⇒ **变差 60%。**

### 4.3 为什么必然变差

`dr_z` 恒为 0（DR 没有竖直里程）⇒ **里程边在 z 维上等于「不变」**，
整个 z 解**只由 19 条回环边决定**，其余 591 帧的 z 全靠插值扩散。
结果是一条**平滑但不真实**的曲线（按段中位 +0.06 到 +0.25 m），把不同帧整体上下错开 ⇒ 叠层变大。

**加一个欠定的自由度，比不要它更糟。**

## 五、判据：什么时候才该开 `enable_z`

| 条件 | 判据 |
|---|---|
| 该录制有没有可估的 z | 回环 z 边绝对值中位 **< 3 cm ⇒ 没有**，不要开 |
| 有没有竖直里程 | `dr_z` 是否非零（当前恒 0 ⇒ 开了就是欠定）|
| 场景是否多层 | 有楼梯/楼层变化才有真值 |

本录制：|z| 中位 **0.030 m** ⇒ **两种判据都说不要开**。

### 7.2 仍然指向的两件事

**① 竖向叠层的真因还没定案。** 审计员实测成品点云的竖向叠层 p50 = **14.03 cm**，
是帧内固有厚度（2.4 cm）的 **11 倍**；地面众数落在 z=−0.025，`[-0.15,0)` 与 `[0,+0.15)` 各占 20%
⇒ **地面被劈成两半摊在 0 两侧**。这与「逐帧 gc 偏差 15% 帧 >5 cm」是同一个量级，但**因果未闭合**。

**② 横向（跨趟）错位**：回环后仍有 34.4 cm（我）vs 6.4 cm（审计员），**两个数都不可靠**
（样本 <15、换参数在 4–13 cm 跳）。横向与竖向是**两个方向**，不能并排比大小。

### 7.3 建议顺序

1. **先把竖向叠层归因闭合**：用「同一 xy 格、不同帧」的 z 差，按「是否同一趟」分组 ——
   如果**跨趟**差异主导，那它就是横向错位的竖向投影；如果**趟内**差异主导，那是 gc/深度问题。
   这一条能一次性决定后面往哪走。
2. **横向**：先固定配对口径（`--max-normal-deg 15` + `--dr`），把样本做到 n≥50，再谈量级。
3. **不要**在没有竖直里程的数据上再开 `enable_z`。
