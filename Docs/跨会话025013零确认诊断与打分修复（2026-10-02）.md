# 跨会话 025013 零确认诊断 + BoW 短文档霸榜修复（2026-10-02）

接 `跨会话地点检索接线P0（2026-10-02）.md` 遗留第 4 条（025013 零确认——待查）与第 1 条（short_map_kf 占拒绝 84%）。诊断脚本 `.tmp/_diag_025013_*.py`，全部结论有实测脚本支撑。

## 结论一：025013 零确认 = yaw 门正确拒绝坏数据（不是 bug，门是成功的）

025013（1259 m / 3495 行 / 1855 特征帧）的 des3d 分布**不差**（88.7% 帧 ≥50、med 248），排除"持久化截断"假说。它每帧都排进检索 top8（打分修复前甚至霸占 top1），但强制验证 395 帧全灭。真正根因：

* **PnP 从特征几何恢复的相对旋转，与存档位姿表旋转 R_old 系统性差 ~116° 纯 yaw**（33 个高内点样本，SVD 平均残差 med 4.5°；R* = 绕 z 轴 116.3° 旋转，第三行 ≈ [0,0,1]）；
* 该会话本身异常：**44% 帧（1541 行）yaw 钉死在 −115°**、dist 长段不变、47% 帧无特征、全程散布 117°/72°/45°/36°（全是 9° 倍数）的 yaw 跳变——一个长时间静止、无真实 HMD 运动的会话，yaw 基准在会话中被外力动过（play space 重置 / HMD 被挪动）；
* 对照组 013519（同夜同管线）对同一查询帧 yaw_err 全部 ~4.5°，完全正常；
* **工程含义：跨会话 yaw 一致性门挡下的正是这种坏会话。零确认是正确行为，6/6 零误检包含这些拒绝。** 不要为 025013 放宽 yaw_tol_deg。

## 结论二：BoW "min" 打分短文档霸榜（真 bug，已修）

* 机理：`score = 交集/min(双方L1)` 在查询/文档词数悬殊时退化为"文档被查询包含度"——查询帧词多（med 390）时几乎必然覆盖短文档（<50 词）的全部词 ⇒ 短文档次次趋近满分 1.0 霸占 top1，把 `verify_max=2` 预算全部挤掉，自己又过不了 `min_inliers=50` 验证门。实测：修复前 025013 排名第一的帧 **89%（353/395）是 short_map_kf**，而 025013 整体只有 11% 短帧；
* 修复：`nav_bow.BowIndex.query_words` 加 `norm` 参数——`"min"`（默认，会话内回环历史口径，**一行未动，参数停调 binding 不受影响**）与 `"l1"`（DBoW2 经典对称口径 `0.5 + 交集/(双方L1之和)`，∈[0.5,1]，对词数悬殊对称）；`XSessionIndex.query` 传 `norm="l1"`；
* 回归测试：`tests/test_nav_xsession.py::TestBowAddWords::test_l1_norm_stops_short_doc_domination`（无关短文档在 min 下 >0.9 复现霸榜，l1 下真匹配必须第一）。
