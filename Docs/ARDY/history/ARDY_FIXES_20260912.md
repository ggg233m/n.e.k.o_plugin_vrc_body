# ARDY 修复与实测（2026-09-12）

> 历史阶段记录：本文保留当时的结果与限制，不代表当前部署或验收状态。当前文档入口见[ARDY文档索引](../README.md)。

本轮集中修复 ARDY，不扩展主模型工具，不绑定字幕，不启动 VRChat。代码已同步主项目和 Unity，SAVE 的绑定位置数据已更新；执行前保存了源文件和场景备份。

## 已修复

1. 接管比例和脚踝高度不再取自实时动画姿势。编辑器同时烘焙根局部空间的19个绑定位置；世界路径换算和骨骼执行使用同一固定比例。骨盆以绑定位置为运动基准，退出时恢复接管前局部位置。
2. 每帧按实际开始发送时间维持至少100ms间隔，不在慢 ACK 后再叠加20ms空等，不追赶积压帧。
3. 单帧 MIDI 发送间隔缩短到0.5ms，但仍保持998条普通事件/滚动秒、112条未确认信用、单个未确认姿态事务和两个停止事件的限制。不修改 VRChat SDK，不扩大缓存，不重发。
4. 仅 motion 的 operation_completed 与 pose_completed 同走优先日志队列，避免普通状态积压使已完成动作被误判超时。宿主仍要求双终态，不把姿态 ACK 当作完成，也未延长完成等待阈值。
5. 服务发布 ready 前增加真实文本、真实根约束、首段及续段的完整执行预热；保留 RNG 状态，清空预热动作历史。模型加载、图预热、完整执行预热分别记录。

- 主场景 ClientSim、真实 NEKO_MIDI、实际 Udon：`003711` 的待机与行走各40姿态帧，均收到 pose_completed、operation_completed，服务 succeeded；结束前端口未停止、outstanding=0。

- 完整回归：**373 passed、1 skipped、301 subtests passed**；Udon 编译通过，Unity 控制台错误0。新增测试确认快速突发仍遵守滚动预算，缺少 ACK 仍停止，慢 ACK 不再叠加帧等待。

## 仍未验收

以上解决了站姿影响比例、部分播放变慢及完成回执误判。鞋底脚滑、动态穿模/扭曲、正常停止后的柔和姿势衔接、跨任务连续生成与后台动作填补、长距离和复杂地形仍需继续验证或实现。脚踝 IK 误差不能代替鞋底滑动指标。主场景行走成功也不等于活动 NEKO 宿主已部署或多人同步已通过。
