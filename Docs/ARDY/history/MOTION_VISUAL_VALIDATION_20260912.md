# ARDY 主场景动作验证：动作质量未通过

> 历史阶段记录：本文保留当时的结果与限制，不代表当前部署或验收状态。当前文档入口见[ARDY文档索引](../README.md)。

本次直接在 Unity SAVE / ClientSim 使用真实 NEKO_MIDI 播放。没有启动 VRChat，也没有修改或保存运行时代码及主场景设置。测试结束已恢复临时关闭的注视功能，销毁观察相机，关闭测试自有模型服务；NPC 的 ESTOP 是测试器收尾行为。

## 结果

| 项目 | 原配置 | 排除注视干扰的对照 |
| --- | --- | --- |
| 4 秒待机 | 双完成回执成功，世界约 4.28 秒 | 双完成回执成功，宿主约 4.73 秒 |
| 接续行走 | world_prepare_unavailable，未播放 | 增加到 3 秒任务间隔后完成，宿主约 4.26 秒，实际位移约 0.428 米 |
| 待机头部相邻采样最大旋转差，排除前 3 帧 | 39.25° | 0.42° |
| 正常结束相邻采样最大旋转差 | 上臂 55.74° / 37ms | 待机上臂 66.10° / 37ms；行走小腿 45.74° / 34ms |
| 接触期脚踝水平漂移 | 最大约 0.014mm | 待机约 0.015mm；行走约 0.055mm |

原配置证据为 `../evidence/motion-visual-20260912/baseline`；对照为 `diagnostic`，包含原始回执、逐次骨架采样、截图索引、指标和约 4fps 的采样动画。原始逐张 PNG 另保留在 H:/AI/NVidia/integrations/motion-visual-20260912-004701 和 motion-visual-20260912-005101。

## 已定位的问题

1. **头颈重复写入。** NekoNpcLife.LateUpdate 仍给头颈叠加注视旋转，没有在 locomotion.externalPoseActive 时让出骨骼控制。ARDY 同时计算全身旋转，产生明显头部跳变。仅在本次对照的播放实例关闭 enableLook 后，待机稳定段头部最大采样差从 39.25° 降至 0.42°。这是强支持证据；两轮未固定生成随机种子、帧率和玩家位置，不是严格同素材性能基准。
2. **正常结束硬恢复。** NekoArdyRigLab.RestoreAnimator 立即写回接管前旋转及骨盆位置，再打开 Animator。对照中没有注视叠加仍出现 46–66° 的单次姿势跳变，结束衔接不合格。起始接管也存在约 20–27° 的相邻采样旋转差，需要一并处理过渡。
3. **旧状态排队导致接续误拒绝。** 原配置 operation_completed 在世界 t=180.644；t=181.254 的心跳 ACK 已是 external，但随后普通队列继续发出旧 action 状态，直到 t=182.421 才发出 external。宿主会被较晚发送的旧状态覆盖，准备检查失败。不能靠把超时或任务间隔永久加长来视为修复；需要处理状态新鲜度/合并及终态后的控制权投影。

## 验证边界

- 对照将原有注视关闭，并把任务间隔从 0.8 秒临时改为 3 秒；该轮待机与行走成功不能用于声称原配置连续动作链通过。临时诊断脚本位于 H:/AI/NVidia/integrations/clientsim_visual_probe.py，主项目验收器未修改。
- 近距离全身截图里可见行走迈腿及根位置变化；没有看到严重肢体拉长，但不能据此排除所有动态穿模或短暂扭曲。
- 脚踝指标来自接触标志下的骨骼位置，**不是鞋底顶点滑动、脚趾滚动或接触力验证**。当前不宣称脚滑问题完全解决。
- 观察采样约 25–35Hz，截图约 4Hz；单张截图额外开销最高约 27ms。耗时不是无观察器性能基准。采样动画不补帧，也不代表完整帧率录像。
- 本次 Unity 控制台错误 0。没有运行与只读验证无关的全套单元测试；上一轮 373 项通过不能代替这次动作质量结果。

## 后续修复顺序

1. ARDY 接管期间让出头颈叠加写入，保留正常模式注视。
2. 完成进入/退出动作的姿势过渡，并明确停止时的控制权时序。
3. 修复旧状态覆盖，使原配置短间隔连续任务可靠执行。
4. 再做鞋底、转向、较长距离步行和连续填补测试。

目前结论是：ARDY 已能在主场景执行待机和短距离行走，但默认配置的动作质量与连续衔接未通过，不能认定为可自然自主探索世界的完整动作系统。
