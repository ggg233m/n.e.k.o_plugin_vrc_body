# ARDY 持续运动协议 v2（候选，未发布）

2026-09-12。主项目与 Unity 主场景已接线，`enableContinuous=false`。服务能力声明 `continuous_protocol=yui-motion-stream/2` 不等于世界可执行；世界必须另外发布 `pose_stream_v2`。旧世界继续使用 v1 和原动作系统。

## 身份与控制帧

### 通信卡顿恢复（2026-09-12）

世界额外声明 `pose_link_recovery_v1` 后，持续发送器将通信故障与人工急停分开。新旧世界不匹配时继续使用旧急停行为，不假定可恢复。

- 通信超时清空发送事务并用单个 `CC(channel=15, number=113, value=1)` 撤销当前运动授权。接收器清空队列、失效旧代次，任务取消；不解除已有急停、不复活旧帧。
- 原 ESTOP 与 CC112 保持人工急停语义。故障后人工急停仍能补发一次，合计不超过两个预留事件。宿主保存恢复阻止标志，只有显式 CLEAR_ESTOP 成功才清除；自动恢复不会发送 CLEAR_ESTOP。
- 同一世界、同一宿主身份在故障发送器退出后允许低频探测，失败退避为2、4、8、15秒。探测要求新的 SNAPSHOT_REQUEST ACK（拒绝重放），随后 STOP、SET_CONTROL_MODE，各阶段复查身份与急停。成功后建立新的 stream_id、姿态代次和生成历史；旧任务保留取消结果，新任务重新提交。
- 接收超时、租约丢失、欠载等通信故障可进入此流程。端口底层写入仍阻塞、客户端进程未恢复或驱动句柄失效时，不保证自动恢复成功。人工急停始终阻止重连接管。

正常逐帧路径不增加 ACK、握手或校验字段；998事件/秒、112未确认事件、2个急停预留、500ms授权期限不变。故障恢复握手只发生在故障后。Unity主场景真实MIDI注入1201ms主线程停顿后已恢复，并验证故障后人工急停保持锁存；此证据不等于VRChat客户端或驱动重启验收。

运动会话 `stream_id` 与语义 `op_id` 分离；`intent_version` 单调递增。世界握手绑定 `world_id + session + pose_epoch + stream_id`。旧身份、旧请求、旧意图不能复活。

所有控制包保持133字节、78个MIDI事件，使用现有单端口调度器。998事件/滚动秒、112未确认事件及急停预留不变。

2026-09-12修正：当旧意图到切换边界的块已确认接收、没有未确认块且候选尚未生成时，`pull/exchange`可附带固定字段`control`描述。宿主立即发送已有的版本8边界标记，同一版本仅一次；不等待GPU，不额外发送续租包。世界仍验证200ms提交边界和当前授权。标记不代表任务开始或完成，不推进播放水位；新帧实际应用后才开始任务。旧宿主可忽略附带字段，已有正常块路径继续兼容。

新意图块只进行一次完整矩阵校验与编码，世界确认代次后只重写epoch及CRC。Udon的CRC16-CCITT使用固定16项查表，每字节两次查表，保留原来的2字节校验和，包格式、预算与500ms授权期限均未改变。复杂路径验证没有移入逐包解析链。

每个意图控制回执另含单调`wire_epoch`。姿态包使用该代次，接收回执另附持续会话`stream_epoch`。替换未锁定的预收帧时，新代次拒绝旧包；语义操作仅在对应帧实际播放时启动。

模式编号预留不等于能力发布。当前宿主公开执行适配器仅允许待机、自由动作及世界验证路径；速度、关键帧和复杂交互尚未完成世界验收。

## 连续时间线

Core40，模型20Hz，历史20模型帧。生成候选不改变已提交历史；每4模型帧一个200ms块，独立保存历史检查点。预收与锁定分开；世界按当前播放时刻计算200ms不可变窗口。新意图从有历史检查点的未来边界生成，当前候选预留1.2秒推理与传输时间。过期推理结果不入队、不污染历史。有限任务生成结束时提前生成基础待机，世界任务完成不关闭运动会话。

线上10Hz，序号从1开始，时间戳为`((sequence-1)*100)%65536`。Unity使用序号展开时钟，接收ACK不改变播放时间。首包建立200ms起始缓冲，最多8个姿态槽，宿主最多提前发送600ms，迟到超过边界时失败退出，不跳播冒充实时。

新意图控制标记仅在意图变化时发送，不按每块发送，以免超过MIDI预算。

## 回执和退出

- `npc.stream_prepared`：准备有效，不代表已接管。包含来源位置、yaw、比例及protocol。
- `npc.stream_armed`：世界已取得身体控制权。
- `npc.stream_control`：语义边界已接受。
- `npc.pose_ack`：接收信用，不能作为实际应用证据。
- `npc.stream_progress`：每4模型帧由实际插值完成回报executed_frame、意图版本和op_id。
- `npc.operation_completed`：有限语义任务的终态；必须匹配世界与会话，并与末块应用一起验证。
- `npc.stream_released`：世界释放身体授权，进入本地交接过渡。

正常退出后，发送器只有在所有在途事务确认且队列清空时才不发ESTOP；否则继续按失败急停处理。后台重连不能解除急停。同身份持续健康时失败不自动重开；只有观测到后端不可用再恢复，才允许新的运动会话握手。急停或世界过期时仍禁止接管；新会话清空旧基础任务缓存。此恢复逻辑已通过模拟健康边沿回归，尚需活动宿主实测。

## 接收流水线

持续协议每个200ms块的两个10Hz姿态可以交叠发送：第一帧已完整写入但ACK尚未返回时，第二帧仅能使用剩余未确认信用。调度器逐事件检查112条上限；未确认信用耗尽时原地等待，不重发、不越界，不释放已取消身份。收到验证过的第一帧ACK后继续同一个第二帧事务。旧v1默认仍使用单帧在途方式。

每个线帧仍独立绑定序号、wire_epoch和端口ticket。错误身份或旧日志不能结清信用。998条/滚动秒、0.5秒回执期限、两条急停预留均保留。测试验证在112条处暂停，缺ACK超时总发送114条。


## 基础路径条件的连续性

路径检查点保存当前生成朝向，按每段先转向、后平滑起步/停止采样；转向上限120度/秒，平移加速度上限0.75m/s²，速度不超过验证计划的max_speed。拐角不在首个模型帧强改朝向。到达型任务时长包括转向、加减速和0.4秒停止余量，不能沿用仅距离/速度的时长。实际成功仍由世界距离与目标状态判定；时长增加本身不算质量验收。


## 实际播放进度附带传输

`npc.pose_ack.stream_progress` 是最多两个由Unity实际Applied产生的记录，字段为op_id、version、executed_frame、committed_frame。接收ACK不再额外占用一条5Hz播放日志；没有反馈超过150ms时世界仍独立发送一条积压播放回执，发送后重置反馈节流。独立stream_progress属于优先回执，避免缓冲等待死锁；总日志预算不变。

宿主提交服务确认时保留原始ACK，并单独传progress_index。服务校验世界/会话/stream_epoch、接收状态和帧界限，再校验嵌入的任务身份。没有实际进度字段的ACK永远不能推进播放水位；任务完成仍必须另有原始operation_completed。旧独立stream_progress回执继续兼容。


## 渲染停顿与传输欠载分离

每个接收槽保存到达时间。只有到达时间晚于该帧播放边界150ms才报告迟到，已及时缓冲的帧不因渲染停顿被误判。LateUpdate最多逐帧追赶4帧，每帧依次做控制权、根碰撞、接触与实际应用检查，不能跳过物理验证。进入过渡的角度预算按渲染帧共享，不能因循环追赶重复放大。播放时钟不重置；500ms授权租约仍保留。

若该次Unity回调本身存在主线程分派间隙，记录额外容差min(400ms,max(0,unscaledDeltaTime−50ms))，并记录因此接纳的帧数与最大容差。实际回调到达时间不被改写；这不能证明原生MIDI包按时到达，也不会恢复已经过期的授权。正常帧间隔下迟到包仍被拒绝。

## 有界服务交换

`POST /streams/exchange` 使用同一运动会话身份，接受可选的received（原始接收回执及wire_epoch）、最多8个applications（原始实际播放回执、可选progress_index与终态）以及布尔pull。服务先校验接收，再校验每个应用进度，最后返回下一块；不是用接收ACK替代执行。已有received、ack和pull接口仍保留。

此接口减少发送关键路径的串行HTTP往返。宿主只有收到成功响应才推进其应用投影；失败进入既有安全关闭，不无限重试不确定交换。后台预热和真实100次切换测试仍独立于此接口单元测试。

## 推理隔离

模型加载、文本编码、图重放与张量运算运行在服务创建的spawn子进程；HTTP、租约和时间线留在主服务。跨进程检查点使用独立CPU数值数组，保留最近20帧；不共享图重放输出存储。单个推理RPC超时为3秒，超时或子进程退出使generator.ready失效，不能通过重新连接复活取消任务。此超时不延长世界500ms授权租约。

持续协议的单包发送间隔为250微秒，旧协议500微秒。普通事件仍服从998条/滚动秒与112条未确认上限；超过生产预算时失败停止，不能追加普通帧突破预算。诊断保留最近32笔端口事务与HTTP请求的有界时序，不记录令牌或请求正文。

## 统一授权与上行仲裁

持续模式下Router、接收器和骨骼执行器都读取Router的500ms授权期限，合法控制切换刷新该期限，不再叠加“最后一个姿态包”的旧接收时钟。只读授权查询不会自行续租；失联或过期不能通过迟到帧恢复。有限v1模式仍保留原接收租约。

姿态ACK、命令ACK和持续控制回执可越过积压的非即时日志；序号在实际出队时分配，事件生成时的状态版本不重写。非回执最多6行/1.05秒、普通快照最多2行，所有日志合计仍不超过20行窗口。操作开始/完成/取消/失败共享state_revision，并携带生成时control_state；宿主既防控制状态倒退，也禁止迟到事件复活同一操作终态。


## 2026-09-12 卡顿恢复与路径窗口修订

以下内容覆盖上文早期实现的同身份禁止恢复和固定5米窗口描述。

- 双方同时声明 `pose_link_recovery_v1` 时，通信故障可以自动执行新的 SNAPSHOT→STOP→SET_CONTROL_MODE 握手。500ms授权期限不放宽；人工急停仍锁存。
- 仅世界明确以 `stream_underrun`、`pose_lease_lost`、`transport_fault` 或 `stream_receive_timeout` 取消的显式到达型路径可以续接。保留语义目标，不保存旧帧；恢复后从世界实际位置重新请求路径，并分配新op_id。完成、被替换、人工停止、世界更换、未确认终态均不续接。新的用户请求立即清除待恢复目标；未知提交响应不重试。
- `execution_status.path_recovery` 记录 previous_op_id 和新提交结果。accepted只是续接受理；最终完成仍要求新op_id的世界operation_completed。自由动作、抓握和空翻不自动从头重播。
- 起播缓冲400ms，提交不可变窗口200ms，模型20Hz、线上姿态10Hz、133字节包、998事件/秒、112未确认事件及两条急停预留均不变。缓冲只改变起播等待，不逐帧拉长播放时间，也不保证任意长度卡顿不断流。
- 新能力 `pose_wrapped_root_v1` 使用姿态包低四位12，高四位仍为接触位；水平根坐标使用毫米有符号16位模编码。世界按相邻值最近分支展开，根窗口不改变世界位置、接触锚点或任务身份，无额外逐帧ACK。旧世界仍使用旧包格式与范围。
- 新能力下宿主路径窗口上限为10km，世界仍校验NavMesh路径走廊、速度、碰撞和场景边界；Rig的旧会话原点5米限制只用于v1。自由动作仍限当前允许区域，不能借此越过路径验证。
- 运动尺度改用模型与角色左右腿长度比；碰撞尺寸保留原身体尺度。宿主速度同步换算，避免短腿角色根位移大于步幅。20Hz到10Hz的接触降采样保留任一子帧抬脚，不吞掉单帧接触释放。
# 2026-09-12 地面路径与曲线拐角扩展

持续能力仍受世界 `enableContinuous` 开关约束，正式场景默认关闭。

- `pose_surface_path_v1`：路径回执保留世界三维位置，宿主保留 `surface_path_xyz`；XZ 按运动尺度和朝向转换给 Root2D，执行器根据当前位置的实际支撑面逐帧更新高度。它不是任意空间飞行或台阶、跳跃、攀爬能力。
- `pose_curved_path_v1`：`npc.stream_path` 可返回与 `points` 等长的 `corner_trims`，单位为世界米，首尾为零。宿主除以运动尺度后使用；旧世界缺少能力时继续使用折线路径。
- 世界可先将内部拐点向可走的外侧移动最多16cm；前后连线必须通过 NavMesh 校验。随后每个拐点最多尝试3种切入长度，每条候选用8段检查导航网格及活动边界；拒绝的拐角切入长度为零。检查只在请求路径时运行。
- 批准的拐角使用两端相切的二次曲线，按曲率限速，沿弧长连续加减速；未批准的拐角仍停步转向。最终执行器仍执行20cm路径走廊、碰撞与局部支撑检查。
- 路径拒绝也返回同一请求的 `npc.stream_path`，`status=failed`，并带明确 `reason`。宿主确认已有控制票据后返回失败，不能继续提交意图，也不能把路径拒绝误报为MIDI超时。
- 地面高度校验使用实际支撑后的根高度，局部8cm上限不变。中心射线落入接缝或命中不可站立的小斜边时，允许使用同一次球形检测取得的有效支撑面；该支撑面仍须满足原坡度门槛，胶囊碰撞检查不变。
- 路径约束采样为500ms；200ms不可变窗口、20Hz模型输出、10Hz线上姿态、133字节包、998事件/秒、112未确认预算和急停预留不变。没有新增逐帧ACK或主模型工具。
