## 新增：候选插件实际发送入口适配

`yui_ardy/runtime/pose_sender.py` 实现独立 worker、32 项有界 mailbox、发送完成 Future 和停止旁路信号；只有 worker 调用底层 sink。共享核心移入候选 `pose_shared_port.py`。`YuiReliableTransport(shared_sender=...)` 可显式接管普通命令、心跳和文字的发送入口；sink 必须与 worker 拥有的对象相同。正常命令只在现有会话验证业务 ACK 后释放端口信用；没有 ACK 时停止，不走旧重发/快照补发路径。共享模式暂停旧上身流。关闭先停心跳、等待 worker 退出再关闭 sink，底层写阻塞时明确报错而不并发关闭。

MidoOutputSink 增加实际 NoteOff 发送支持，避免把压缩数据错误变成 NoteOn。未注入共享发送器时保留旧执行路径。仍未在运行中的宿主启用，不自动暴露新能力。

验证：完整候选回归 274 passed、1 skipped、292 subtests passed；随后增补两项测试，最新适配专项 5 项通过，覆盖真实 YuiReliableTransport 心跳/急停入口、并发打断半帧、底层失败不重试、普通命令缺 ACK 不重发及 worker ACK 释放信用。测试使用真实候选类和内存 sink，不代表原生端口下的多线程性能已通过。

待完成的运行绑定：姿态包的 wire sequence 必须与 worker 返回 ticket 关联，经活动世界/驱动/会话/代次验证后才调用 ack；不能直接用未验证日志释放信用。mailbox 接收内部 ticket，不是直接接受外部姿态序号。当前 worker 使用 sleep(0) 与 perf_counter，常驻 CPU 和唤醒开销还需优化/实测。运行启停、重连与端口唯一所有权也需要接入后端生命周期。明确完成这些项后才能开启真实宿主测试。

## 新增：统一端口调度核心

`shared_port.py` 统一管理 control、heartbeat、pose、text；队列最多 16 个事务，姿态最多一个未确认帧，正常未确认消息总数最多 112 条，另保留两个停止事件。总滑动秒正常发送不超过 998 条；停止绕过普通队列并锁存。一个事务内寄存器不交错；停止可打断半帧，其余高优先级事务在当前事务结束后调度。

仅匹配当前 session/epoch 与完整已发送事务顺序号的 control/pose ACK 能释放信用。该 ACK 的发送顺序水位只证明同一原生 MIDI 输入此前的数据已读过，不替代其他普通命令的业务 ACK 或 operation_completed。迟到 ACK 不解锁，发送异常按可能已发出处理并停止，不重试。没有 ACK 的心跳和文字也占信用；无法取得新的读取进度时超时停止，而非无限续发。

核心为单线程 actor，所有 submit/step/ack/stop 必须由同一个调度线程处理。正式适配尚未实现：现有 `YuiReliableTransport` 的心跳线程、普通命令等待、文字、上身流和 sink 生命周期都需要统一转交该 actor；不得从其他线程直接调用。旧上身流与全身流需互斥。现有正式插件仍按旧方式运行，不启用 ARDY 执行。

实测 `send_shared_probe.py`：控制/心跳/文字用通道 14 的无动作 CC 模拟负载，姿态走通道 15；没有发送正式 NPC 命令。发送 378 条（312 姿态消息、64 模拟旧通道消息、2 停止），另 1 条探针结束；3 帧 ACK、最大未确认 99 条。第 4 帧期间停止轮询约 1 秒，发送端 receipt_timeout 后停止；原版 SDK 无异常，接收器 accepted/submitted 均为 3。证据 `shared-send-result.json`、`shared-native-result.json`。这不等同于真实旧命令混合业务通过。

探针最初因当前 Windows/Python 的计时分辨率使发送过慢，在 32 条未确认时超时停止（`shared-timer-failure.json`）。改用 perf_counter 时钟门控后通过；短时探针 sleep(0) 让出线程，正式 worker 的 CPU 开销和时钟调度尚待验证。

调度、门控、编码及 ACK 共 11 项 Python 测试通过。下一步：生产 actor 适配与停止并发测试、真实遥测回传预算、Udon VM、当前 VRChat 客户端。以下历史修订描述中的旧预算以本节和机器配置为准。

## 新增：日志回执与延迟提交

世界脚本新增 `npc.pose_ack`，字段为 `pose_session`、`pose_epoch`、`pose_sequence`、`state=received`。正式绑定通过现有 `NekoNpcTelemetry.EmitForced`，要求遥测会话匹配；其共享 20 行/秒预算和排队可能影响吞吐及超时，尚未完成真实世界绑定与混合负载验证。实验开关 `editorLogProbe` 默认为 false，仅实验时输出 `[NEKO_ARDY_LAB]`；正式解析默认拒绝该标记。

`pose_ack.py` 只解析接收回执，严格检查正整数身份字段，拒绝把 operation_completed 或 completed 状态当成信用。正式宿主仍需结合活动世界/驱动身份、日志轮转和服务实例做路由；当前接收测试读取 Editor.log，不是 VRChat output_log。

接收端在帧开始、完整包解码前及提交前检查 500ms 接收租约；超时锁存并增加代次。解码只设置待提交标记，LateUpdate 才执行批准与 ACK；同批次停止先清除待提交标记。不写角色骨骼。这里的接收租约不是完整的播放时间戳协议，短于租约的迟到及时间轴回绕仍需后续处理。

原版 SDK 实测：`log_probe.cs.txt` 在第三帧后暂停输入轮询，Python 的 `send_log_probe.py` 只读取真实 Editor.log 回执。发送 4 帧、确认 3 帧；最大轮询间隔 1.095 秒，第四帧在恢复时被租约拦截，accepted=3、submitted=3、stopped=true，无 SDK 异常。共 314 条消息包括一次停止和一次探针结束。证据：`log-native-result.json`、`log-send-result.json`。

编辑器代理额外验证同批次停止撤销提交及超时拦截；Python 编码/门控/回执解析共 7 项测试通过；重新强制 Udon 编译后程序及序列化程序均存在、控制台 0 错误（`log-ack-udon-compile.json`）。没有执行 Udon VM 或真实 VRChat。

下一步仍为统一端口的总信用调度、生产回执会话路由和 Udon 运行验证；现有旧发送器尚未接到该门控，不能并发开启正式全身姿态流。

## 新增：单帧信用门控

仅限速不能限制卡顿期间的积压。`flow_gate.py` 增加独立姿态接收 ACK 门控：同一会话和代次最多一个未确认帧（78 条消息）；收到完整匹配的顺序号 ACK 后才释放信用。500ms 超时或明确停止后锁存，迟到/重复/其他会话 ACK 不得解锁，不自动重传或补发。普通 npc.ack 不能替代姿态帧 ACK；接收确认也不是 operation_completed。

2026-09-11 原版 SDK 实验：`credit_probe.cs.txt` 在第三帧后暂停 MIDI 轮询 1 秒。发送端只发送第四帧，然后等待 ACK 超时并发送一次实验停止标记；没有第五帧。恢复轮询后总计收到 4 帧、314 条消息（312 姿态、1 停止、1 结束），无 SDK 越界；实测最大轮询间隔 1.093 秒。证据：`credit-send-result.json`、`credit-native-result.json`。门控与编码共 6 项测试通过。

此实验用编辑器文件回传 ACK，正式世界不能照搬该通道。尚需实现姿态 ACK 的世界回传及吞吐验证。原版两个 SDK 文件哈希仍与备份一致。

边界：第四帧在恢复轮询后仍被解码接收，因为它先于停止消息入队；这不证明迟到姿态不会应用。正式执行器必须缓冲完整一轮输入，处理停止/有效期后再提交骨骼，并设计可验证的播放期限。当前探针不应用骨骼，也未验证 Udon Update 看门狗。

单帧信用只限制此发送器的姿态消息。传统心跳、文字、其他进程仍可能填满同一个输入缓冲；正式集成必须由同一端口调度器限制所有未确认消息并为停止保留余量，不能把 78<128 当作总输入安全证明。

用户已授权调整协议。本修订取代“必须受旧总预算 200 条/秒约束”的设计前提，但不自动修改正式插件限流或宣告世界就绪。

## 数据与调度

- ARDY 保留原始 20 FPS 输出；候选传输 10 FPS、每帧 78 条消息，即 780 条/秒。世界端按时间轴插值；插值、关键接触帧保留和脚底锁定尚待实现与视觉验收，不能只丢弃一半帧就报告动作质量不变。
- 单个端口使用统一调度器：候选滑动一秒总预算 1000 条，其中姿态最多 800，传统正常消息最多 199，急停保留 1。心跳包含在传统预算内，不额外叠加。总计混合流量尚未验证，这些是拟定上限而非性能实测。
- 急停最高优先级，可中断未完成姿态帧；之后明确终止该帧并增加代次。原控制与心跳优先于姿态，文字让位于控制。姿态不得通过另一个独立发送器绕过端口总限流。
- 帧内均匀发送，不集中发送 78 条突发。超时或被抢占而赶不上播放期限的帧丢弃；不积压并突发补发。重新开帧清理旧半包。迟到、旧会话、旧代次与 CRC 不符的数据不得应用。
- 延用通道 15 的 NoteOff 数据与 CC 110/111 帧边界、112 实验急停。CC 113 仅为探针结束标记，不属于正式运行控制协议。
- 目前 `frame_ms` 为 16 位字段；正式长时间播放前必须定义回绕和任务时间基准，或升版扩展字段。当前固定姿态吞吐样本没有验证播放时间轴。
- 若新能力未协商、后端未连接或持续欠载，维持传统导航与动作入口；不得发布 `execution_ready=true`。急停后必须明确解锁，禁止自动恢复。

历史机器可读参数见 [protocol-candidate.json](history/protocol-candidate.json)，仅作旧候选快照，不用于配置当前运行时。统一调度、插值、世界能力协商和真实世界 ACK 都是后续实施项，当前探针不替代这些组件。
