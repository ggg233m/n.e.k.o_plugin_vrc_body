## 一、一句话结论

在线链路的真瓶颈是**消费循环只跑 0.97 Hz**（采集侧 8.83 Hz），而**不是算力**——
全部已有埋点合计只占运行时长的 2.4%。消费掉到 1 Hz 的原因是
`VisionWorker` 的"建图优先"捷径在**建图停止后不再生效**，每帧退回去跑
光流 + 深度 + 检测的重路径。建图停止本身是**一个 stop 动作**造成的，不是崩溃。

## 三、根因链（每层都标证据）

1. **有人下发了 `mapping_stop`** → `reason="mapping_stopped"`、`mode="idle"`。
   证据：该字符串只在 `LiveMappingSession.stop()`（`live_mapping.py:281-289`）产生，
   而 `stop()` 只被 `service.mapping_stop()`（`service.py:866`）调用。
   置信度：**高**（唯一写入点，无其他路径）。是否预期行为需人工确认。
2. **停之前先吃过一次 >2.5 s 断档** → `last_reset_reason="timestamp_gap_reset"`、
   `last_result.state="LOST"`（`live_mapping.py:321-330`）。
3. **`state != "mapping"` ⇒ `mapping_priority` 捷径不生效** →
   每帧走 `_estimate_traversability` + `_estimate_ground_extent` + `depth_provider`
   + `runtime.process_frame`（`vision.py:2577-2625`）。
   作者注释自述这条重路径会把消费者拖到 1–2 Hz（`vision.py:2549-2551`）。
   置信度：**高**（实测量级与注释吻合）。
4. **消费 0.97 Hz ⇒ 队列 `maxsize=1` 丢掉 88.9% 的帧** → 下游全部缺输入。
5. **下游症状**：
   - 重定位 0/2115，`reason="no_geometric_candidate"`；
   - 尺度 `reason="visual_tracking_not_stable"`，`reject_counts.no_visual_pose=430`；
   - 建图 `init_frames=43 / 141`（30% 的帧花在初始化上，1 Hz 下就是 43 秒）。

**另一条独立缺陷（与 1–5 无因果，但同样阻断重定位）**
观察器加载的是离线图 `relocalization_map.json`（**49 kf / 4216 pts**，
`revision=c747255a...`），而在建的是 `relocalization_map_live.json`（**19 kf / 3265 pts**）。
⇒ 拿离线图匹配实时画面，**永远不会有候选**，与检索参数无关。置信度：**高**（两个文件与两个计数字段直接对照）。

| 5 | **谁慢** | 同上，比较 `queue_wait` 与各阶段 median | `queue_wait` 远大于各阶段 ⇒ 输入不够；某阶段 ≈ 周期 ⇒ 该阶段是瓶颈 | —— |
| 6 | 消费帧率 | 30 s 差分 `vision_worker.frames_processed` | 建图期应 ≥10 Hz | 仍 ≈1 Hz ⇒ 捷径未生效，回到第 3 层 |
| 7 | 重定位是否开始命中 | `/worldmodel/relocalization` → `localized_frames` | 应 >0 | 恒 0 ⇒ 先解决"图不对"（第四节末段） |

**判定规则**：第 5 项的读数决定下一步动哪一侧——
`queue_wait` 大 ⇒ 动采集（`interval_s` / WGC 抓帧开销）；
某阶段大 ⇒ 动该阶段（深度推理 / 光流 / `runtime.process_frame`）。
**在拿到第 5 项之前，不改任何运行参数**（沿用"先 profiling 再改参数"）。

## 五、风险与明确不做的事

- ⚠️ 不要把建图期 `frame_rate`（本轮 ≈5.59）当成链路整体速率——那是
  `mapping_priority` 生效时的数；停止后是 0.97 Hz。**混用会得出完全错误的结论。**
- ⚠️ 不要为了提帧率直接调小 `interval_s`：采集端自身只有 8.83 Hz（目标 30），
  说明 WGC 抓 1905×1119 + 编码已吃掉差额，单纯调小间隔会推高 CPU 而不提产帧。
- 未动：上游采集频率、`max_jump_rotation_deg`、SLAM 内部参数、⑥ 受控录制、⑦ LLM 地图工具层。
- 本会话内 `test_offline_harness_isolation` / `test_check_recording_channels` / `test_route_v2`
  的 19 条红测是 **harness `safe-delete` 守卫拦截临时目录删除**所致，非代码问题，
  且三者都不 import `backend/vision.py`；但**这 19 条本会话未能实跑收口**，列为遗留。
