### 17.8 四条硬性路线约束（用户 2026-09-20 定稿，立即生效；**第 4 条 2026-09-30 修订**）

1. **静止帧过滤必须在候选生成之前。**
   静止画面只能用于地点描述或关键帧保留，**不能直接产生回环边**。
   ⚠️ 诚实标注：本段素材静止帧只占 4.5%（58/1297），这道门**在本素材上影响很小**；
   `overlap_new.py` 的"无门 98% 假通过"来自另一段静止占 70% 的录制。
   作为**设计约束**保留（换素材/换录制脚本后静止段会回来），但不要拿本素材的
   结果声称"已证明这条门有效"。
2. **`AngularY` 不得积分为实际朝向。**
   经验图边的朝向只能来自：① 我们发出的转向指令和时长 ② 视觉重访证据 ③ 语义方向确认。
   依据：8 位量化步长 8、阶跃 <32ms 无可观测惯性、幂律 p≈3.2（输入整形签名）；
   同为轴值 0.6，turn-s 0.6 → 2.3×、turn-s 2.26 → 4.2×、鼠标通道 → 1.03×，
   **不存在单一标定系数**。
   > **出处可溯源**：量化步长 / 饱和上限（±1024）/ 幂律可由原始数据
   > `.slam_probe/offline_probe/recorder/runs/axis-*` 的 `osc.jsonl` 独立复现；
   > 端到端定标与阶跃响应见 `.workbuddy/memory/2026-09-19.md`
   > （含两次"判定可用 → 被端到端实测推翻"的完整实验记录）。
   > ⚠️ 轴值 1.0 的"低离散"是**饱和削顶**假象（约 2.9% 样本钉死在 1024），
   > 标定与实战一律 **轴值 ≤0.6**。
3. **深度统一用 OpenVINO GPU fp32，不再做 INT8 基准或量化接入。**
   已实测：OpenVINO GPU fp32 **28.5 ms**；**INT8 在 Arc 上反而 453 ms（慢 16 倍）**。
   §7 里"必测 A770 上 252×252 FP16/INT8"这一项**撤销**（FP16 仍可选测）。
4. **完整 SLAM / 全局 BA 按"环"分区，不按"做/不做"划线。**（**2026-09-30 修订：原全文禁令连同它的理由一并作废**）
   - **在线 20 Hz 环**：只允许 **2-DoF 线性拉普拉斯求解**（`backend/nav_loop.py` 的
     `LoopCloser.optimize()`，实测 **3.30 ms@n=55 ～ 12.52 ms@n=886**）。禁止残差为 SE(3)、
     含 3D 点、或复杂度随图**超线性增长**的求解器进这个环。
   - **会话结束 / 空闲 / 按需 / 离线**：**允许**局部或全局 PGO，但四个入场条件必须同时满足——
     ① **边权同口径**（米制；回环 σ 随两帧距离增长；追踪米↔世界米的换算只经 `pose_math.py` 这一处）；
     ② 保留 **Cauchy IRLS** 鲁棒核；③ 残差**向量化且与原实现逐元素对拍**（复用
     `research/tools/pose_graph4.py` 的 6 条回归门）；④ **必须有独立验证指标**才能采纳结果
     （跨会话 ATE / 回环与独立里程一致性 / 回到已知起点的误差）。**没有验证的全局优化＝伪造。**
   - **永远不做**：把 3D 点或视觉重投影放进状态（`3D点云可救性评估.md` 已判点云不可作几何真值）；
     学习型米制深度当发布米值。
   - **触发降级**（出现任一条，就把在线侧进一步收紧为"连离线也不做"）：跨会话单点约束使远处
     误差超阈值；需要 **3 个以上会话**合并；朝向通道失效（非 VR / 混用 `LookHorizontal` / recenter）
     使"2-DoF 的前提＝HMD yaw 精确"崩塌（那时回环边必须参与约束朝向 ⇒ 至少 3-DoF）。
   当前建图方式（**不变**）：已知指令主动扫描 → 关键帧+局部深度片段 → BoW Top-K 检索 →
   ORB 几何确认 → 多帧/语义确认 → 经验图回环边 → 局部深度占用图避障；
   **不求厘米级全局坐标** —— 这是**输出契约**（§14 只发相对量 + 误差）的要求，
   **不是"BA 原理不可行"**。

   > **为什么改（旧理由已被后续工作推翻；四次失效记录原样保留为踩坑证据）**
   > 原条文写的是"度量位姿与尺度约束不稳定：位姿图优化两次尝试路径 +70% / +350%，
   > 根因是回环边与里程计边尺度不可比"。这四次失效的根因是**四类可修复的工程缺陷**：
   > ① **坏回环直接进图** —— `SLAM米制复测报告（2026-09-24）.md:236`：视觉回环"2 好 7 坏"，
   > 只含 3 条回环边的 2D 位姿图融合把 DR 路程 **7.11 → 3.19 m**（`pull_max = 6.42 m`），
   > 该文原话"这不是「闭环修正」，这是被坏约束带跑" ⇒ 后来才建的**四级确认协议 +
   > `min_inliers` + HMD yaw 门 + Cauchy IRLS**（§14/§18/§20）正是解药；
   > ② **稠密 Hessian + O(n³) 求解**使单次 `optimize` 占整轮墙钟 **63%**
   > （`在线建图停滞-根因与修复（2026-09-23）.md:21,53`）⇒ 已换稀疏解；
   > ③ **位姿图结果写回每一个关键帧**把地图几何撕碎；`丢跟踪根因-图优化撕碎地图几何（2026-09-23）.md:197-199`
   > 自己写着"严格做法仍是让点云跟随**单一全局 SE(3)**，或直接上真正的 BA。记为待办" ⇒
   > 这条待办被原条文一句话挡住了，**现在退回待办**；
   > ④ 6.8–11.3 s 出自**回放脚本**里那份 4-DoF `PoseGraph4`（纯 Python 逐边残差 9.5 ms ×
   > 722 次数值雅可比），**不在在线链路**；向量化后单次 ÷60、整体 ÷15、端到端回环步 ÷6.4，
   > 已落仓 `research/tools/pose_graph4.py` + 6 条回归门 + 变异验证（`回环优化耗时剖析（2026-09-29）.md`）。
   > ⚠️ 原条文引用的 "+70% / +350%" **原始实验记录不在现行文档集合内**（按本仓规矩，数字必须可溯源）。
   > **本修订自带证伪条件**：若在"确认协议已建、σ 已同口径、求解器已稀疏化"的条件下重跑
   > 仍出现路径被拉长，则本修订作废、恢复全文禁令。
